# 太阳系漫游指南 · 示例素材

这是 [`examples/solar-motion.yaml`](../../solar-motion.yaml) 的配套素材与版面生成器。
**复刻对象**是用户提供的太阳系演示视频（网页版，Three.js + GSAP）。

---

## 这份样例在证明什么

配方「**动效来自页与页的差异**」原先只有机制层断言（`test_morph.py`），
没有一份**端到端**的完整样例。这份样例补上了它，而且刻意选了
机制断言**测不到**的事当作判据：

| 判据 | 为什么机制断言测不到 |
| --- | --- |
| 跨页同名形状**全部成对**（8 页 × 39 形状 = 312 对） | `test_morph` 只在一对形状上测配对，不测"整套版面里有没有漏" |
| **同名形状的 shape id 逐值相同** | Morph 按 **id** 配对（不是 name）—— id 错位时结构检查全绿、放映看不到补间 |
| 每对行星在两页之间位置/尺寸**都不同** | 相同 = 没有差异 = Morph 退化成硬切。**看起来完全正常**，只是不补间 |
| 详情页里非当前行星组**全部在画布外** | 「挪出画布」是退场设计（见下节）。缩成小点堆到角落也"看不见"，但观感完全不同 |
| 相邻页里可见形状**都有差异** | 详情页没有页内 timing（见下），过渡全靠差异；无差异 = 该形状一动不动 |
| 只有总览页带 `<p:timing>` | 详情页的页内 entrance 会把形状**踢出 Morph 补间**（实测，见下） |

判据在 `tests/test_docs.py` 第 27 组（23 条），结构复核副本
`tests/fixtures/solar-system-structure.pptx`（由 `tools/make_solar_fixture.py` 制作，
洗 `docProps` 并当场断言"结构与源逐值相等"）。

**三个负样本全部验过**（2026-10-12）：把某颗非当前行星挪回画布内 → 报
`在外 223/224；留在画布内: s4:PLANET_1`；把某形状改成与上一页完全相同 →
报 `s5:HDR_CN`；给详情页塞回 `<p:timing>` → 报 `共 2 页带 timing`。

## 设计：那么多元素，在页与页之间怎么切换

这是这份样例真正的设计部分。**Morph 不关心"你想让什么动"**——它只做一件事：
逐对比较两页里**同 id 的形状**，把差异补成动画。所以设计动作 = 设计**差异**。

每个组（行星 + 引线 + 中英标签，共 39 个形状）在任何一页只有**三种状态**：

| 状态 | 长什么样 | 用在哪 |
| --- | --- | --- |
| **带里** | 八组等距排成一条带，y=250pt 一行 | 总览页 |
| **聚焦** | 画布中央放大，引线加长、变金色 | 该行星自己的详情页 |
| **画布外** | 整组平移到画布外（左右两个停靠区） | 其余 7 页 |

「画布外」是关键设计，有两个容易做错的地方：

1. **不要缩小后堆到画布内的角落。** Morph 会忠实执行这个指令——观众看到
   七颗行星带着引线标签一起飞向角落、缩成一团小点。那不是"退场"，是"乱"。
   退场的正确指令是**挪出画布**：滑出画面在任何尺寸下都成立，且方向即语义。
   （实测踩过：旧版用 2pt 停靠左下角，视频抽帧里就是一团东西飞过去。）
2. **平移量按"整组"算。** 同一侧的行星共享同一个位移量（由"最近的一颗恰好
   停在画布外"定出），带上的间距因此保持——整队像一列火车平移出站，
   **位移一致 = 速度一致**，这是 Morph 页面看起来"稳"的原因。

于是每一跳的动作都是确定的：

    总览 → 水星页：水星升中央放大（+230, 放大 3.3×）；
                   其余 7 组整队右移 +764 滑出；太阳左滑出；标题块微下沉
    水星页 → 金星页：金星从右外侧 1100 → 中央 480（-620）；
                    水星从中央 480 → 左外侧 -140（-620，与进场对称）；
                    其余组整队前移一格（-85.7）；画布外元素不露头

坐标由 `build_deck.py` 的 `group_geom(i, page_j)` 一处决定，spec 不重复描述——
**版面与动效分开维护**。

### 两条实测得来的 Morph 规则（2026-10-12，视频逐帧验证）

1. **详情页不能有页内 entrance 动画。** 一个形状如果在本页有 entrance，
   它就**不参与 Morph 补间**——先淡出、等 Morph 结束再重新入场。
   视频帧证据：带页内动画的方块在 3.17s 淡出、4.17s 才从画面底部重新飞入。
   所以详情页的 spec 是**零 effects**，过渡完全交给页面切换。
   （唯一例外是总览页：它是第一页，没有"上一页"，入场只能靠 timing。）
2. **总览页的入场用 `with` + 绝对时间表。** 见 [`../../solar-motion.yaml`](../../solar-motion.yaml)
   的注释：`with` 的效果归入同一组、delay 相对**组的开始**，写的就是
   "这一幕在第几秒发生"。整段入场 ~2.9s。

## 放弃的能力（网页独有，PPT 做不到）

| 视频里有 | PPT 里 | 为什么 |
| --- | --- | --- |
| 鼠标悬停出「点击行星…」 | ❌ 放弃 | PPT 的「动作」只能跳页，不能改变画面状态 |
| 点击行星聚焦放大 3D 球体 | ❌ 放弃 | 同上 —— 没有 JS 运行时 |
| 方向键翻页 | ✅ | 切换效果，PowerPoint 原生 |
| 太阳从左侧升起 | ✅ 强化 | `zoom` + `smooth`，比视频更稳 |
| 细线引线标注 | ✅ | 直线连接符 + `wipe` 生长 |
| 逐行星入场 | ✅ | `with` + 绝对时间表，每颗错开 0.135s（"由近及远依次点亮"） |

## 素材：程序化生成，不用图像 API

`make_assets.py` 用纯 `numpy` + `PIL` 生成全部贴图。三个理由：

1. **不外发任何请求** —— 仓库是 public 的，素材入库等于发布内容
2. **可复现** —— 同一份代码永远产出同一张图。**这才可能写"逐值核对"的判据**；
   AI 生图每次都不一样，判据无从写起
3. **物理细节可控** —— 明暗界线（terminator）的柔和过渡带、土星环的
   卡西尼缝与前后遮挡、木星条带，都是程序化能精确控制、生成模型常常画错的

### 已踩过的坑（都写在代码注释里）

| 症状 | 根因 | 修法 |
| --- | --- | --- |
| 土星环是**虚线**，位置偏低 | 按角度逐度画 `line` → 短直线段 | 反投影成椭圆，一次填多边形（3600 采样） |
| 球上**方块状色阶** | 银河雾量化到 uint8 出现台阶 | 抖动幅度必须 ≤ 信号的 8%，并做 1.8px 二次平滑 |
| 抖动变成**紫色噪点带** | 抖动放大到与信号同量级 | 同上 —— 抖动只做最后 1~2 个色阶的 dither |
| 木星条带**消失** | `base*shade` 把条带对比压到 2% 以下 | 抽掉光照局部均值再乘回，只留条带 |
| 木星变**白球** | 局部均值归一化时多乘 255 | `lm` 是比值（≈1），`base` 是 0..255，量纲差 255 倍 |
| 木星变**黑球** | `lm` 背光侧接近 0，除以它溢出 | 钳下限 0.30，不在背光侧做除法 |
| 条带边缘有**细台阶** | 相邻色带交界硬转折 | 输出后 0.4px 软化 |

### ⚠️ 比例是**视觉可读**，不是真实比例

真实比例下地球只有 1 个像素宽（太阳直径是地球的 109 倍）。
这里的直径与距离刻意做成"看得清"的：

| 行星 | 总览页直径 | 详情页直径 |
| --- | --- | --- |
| 水星 | 46 pt | 150 pt |
| 金星 | 62 pt | 190 pt |
| 地球 | 70 pt | 230 pt |
| 火星 | 58 pt | 180 pt |
| 木星 | 116 pt | 320 pt |
| 土星 | 104 pt | 290 pt |
| 天王星 | 76 pt | 220 pt |
| 海王星 | 72 pt | 215 pt |

**这在科普意义上是不准确的。** 要拿去讲科学，比例必须按真实值重排
（本目录的生成器改一行 `PLANETS` 表即可），并接受"地球看不见"的后果。

## 重建方式

```bash
# 1) 素材（约 20 秒，纯本地）
python examples/material/solar/make_assets.py

# 2) 版面 —— 三阶段。中间必须过 PowerPoint 的复制页（它保住 shape id，
#    而 Morph 按 id 配对；手工建页 id 会错位）
python examples/material/solar/build_deck.py --stage=1   # 总览 + 1 页详情模板
#    → 在 PowerPoint 里把【第 2 页】用 Duplicate() 复制到 9 页
python examples/material/solar/build_deck.py --stage=3   # 填每页数值 + 校验 id 对齐

# 3) 注入动效（几何零改写）
python scripts/motion.py apply \
  --pptx examples/material/solar/solar-system.pptx \
  --spec examples/solar-motion.yaml \
  --out out/solar.pptx --assert-geometry

# 4) 覆盖率审计（普通页看效果覆盖，morph 页看跨页差异）
python scripts/check_coverage.py --pptx out/solar.pptx \
  --spec examples/solar-motion.yaml --footer "太阳系漫游指南"

# 5) 结构复核副本
python tools/make_solar_fixture.py

# 6) 真渲染 + 往返验证（需要 PowerPoint）
powershell -NoProfile -File scripts/motion.ps1 \
  -Pptx out/solar.pptx -Spec examples/solar-motion.yaml -OutDir out/solar -ExportPdf
```

**版面与动效必须分开生成** —— 这条是本项目的铁律。
改版面不影响 spec，改 spec 不影响版面；两者靠 shape `name` 相连。
所以 `build_deck.py` 里那些 `PLANET_*` / `LEAD_*` / `LABEL_*` / `CN_*`
的命名规则是**硬约定**，改名 = 断掉 Morph 配对。

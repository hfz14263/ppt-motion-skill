# 3D 相机与旋转:参数 → **实测**结果

每一个数都是**在这台机器上渲染出来量到的**,不是从规范抄的。
机器可读版 `scripts/camera_reference.json`;测量脚本 `scripts/build_camera_table.py`。

---

## 1. 为什么要有这份表

做"立体版"效果时,同一类问题反复出现:**参数被接受 ≠ 参数有效 ≠ 结果如你所想。**
实测到四种脱节:

| 类型 | 实例 |
| --- | --- |
| 参数变了,**结果没变** | 五个透视预设渲染完全相同;`PresetThreeDFormat` 接受值但投影不变 |
| **名字和语义相反** | `Perspective = 0` 与 `= 1` 都是"平行",`-1` 才是"透视" |
| **两套参数轴不对应** | 窗格 `RotationX/Y` ≠ OOXML `lat/lon` |
| **值域越界不是忽略,是拒绝** | `lat=21600000`(规范给的上界)让**整个文件损坏** |

**所以:参数要当"待测对象",不是"待查文档"。**

---

## 2. `camera` 元素结构(ECMA-376)

```xml
<a:scene3d>
  <a:camera prst="perspectiveFront" fov="5400000" zoom="100000">
    <a:rot lat="18600000" lon="0" rev="0"/>
  </a:camera>
  <a:lightRig rig="threePt" dir="t"/>
</a:scene3d>
```

| 属性 | 类型 | 规范值域 | **实测可接受** |
| --- | --- | --- | --- |
| `prst` | `ST_PresetCameraType` | 62 个枚举名 | ✅ 全部可用,见 §3 |
| `fov` | `ST_FOVAngle` | 0 ~ 180°(1/60000 度) | ✅ 0 ~ **10800000**,与规范一致 |
| `zoom` | `ST_PositivePercentage` | 1/1000 百分比,默认 100000 | ⚠️ **不做范围校验**,连 `2147483647` 都收 |
| `lat` / `lon` / `rev` | `CT_SphereCoords` | **0 ~ 21600000** | ❌ **实为 0 ~ 21599999** |

### ⚠️ 规范的上界会毁文件

**`lat` / `lon` / `rev` 写 `21600000`(规范明写的合法上界)时,
PowerPoint 报 `0x80070570` —— 文件或目录损坏且无法读取。真实上界 `21599999`。**

```python
def norm(deg):
    """角度 -> OOXML 安全值。负数和大值都会毁文件,必须归一化。"""
    v = int(round(deg * 60000)) % 21600000
    return v if v < 21600000 else 21599999
```

`0x80070570` 在 OOXML 注入里**几乎总是指"属性值越界或结构非法"**,不是文件真的坏。

## 3. 62 个预设:名字决定**投影类别**

`MsoPresetCamera`(`Microsoft.Office.Core`,1~62)官方名称,全部实测。
**在显式给了 `lat` 的条件下**(这样测才只反映投影类型):

| 枚举 | 预设 | 投影 | 收敛比 |
| --- | --- | --- | --- |
| 1–9 | `legacyOblique*` | 平行 | ~1.000 |
| 10–18 | `legacyPerspective*` | **透视** | 0.74 |
| 19 | `orthographicFront` | 平行 | 1.000 |
| 20–39 | `isometric*` | 平行 | ~1.000 |
| 40–47 | `oblique*` | 平行 | ~1.000 |
| 48–58 | `perspective*` | **透视** | 0.92 |
| 59–60 | `perspectiveHeroicExtreme*` | **透视(最强)** | 0.84 |
| 61–62 | `perspectiveRelaxed*` | **透视** | 0.92 |

### 三条能省下大量试错的结论

1. **只有 `perspective*` 和 `legacyPerspective*` 会产生透视。**
   其余 47 个(`oblique*` / `isometric*` / `orthographicFront`)
   **全是平行投影、永远没有灭点** —— 平面不可能躺下去,角度怎么调都没用。

2. **"适度宽松"和"宽松"渲染完全相同**(都是 0.917)。选哪个都行。

3. **在显式 `lat` 下,同一个类别内部的预设差异极小** ——
   48–58 那十一个实测收敛比**完全一致(0.917)**。原因:**`lat` 会覆盖预设自带的角度**,
   于是预设只剩"平行还是透视"这一位信息在起作用。

   > **预设选类别,角度靠 `lat/lon`。**

## 4. 预设**自带**的角度(规范里没有,只能实测反推)

ECMA-376 对 `@prst` 只说:

> "The preset camera defines a **starting point** for common preset rotations in space."

**规范定义了 62 个名字,但从不公布它们的角度。** 而且预设不写 `<a:rot>` 时,
**文件里也没有角度** —— 角度是 PowerPoint 内部的,不落盘。所以只能量出来。

方法是把平面投影后的四个角点取出来,量两根轴各自的缩短比例,反推 pitch/yaw。
**这个反推是校准过的**(见 §5)。

不写 `<a:rot>`,只给 `prst` 时的实测结果:

| 预设 | 收敛比 | 反推 pitch | 反推 yaw |
| --- | --- | --- | --- |
| `perspectiveRelaxed` | 0.856 | 49.9° | 0° |
| `perspectiveRelaxedModerately` | 0.888 | 35.1° | 0° |
| `perspectiveAbove` | 0.933 | 19.5° | 0° |
| `perspectiveAboveLeftFacing` / `RightFacing` | 0.979 | 37.3° | 0° |
| `perspectiveBelow` | 1.072 | 19.5° | 0° |
| `perspectiveHeroicLeftFacing` / `RightFacing` | 0.884 | 0° | **10.2° / 8.7°** |
| `perspectiveLeft` / `Right` | 1.000 | 0° | **20.4°** |
| `isometricTopUp` / `TopDown` / `BottomUp` / `BottomDown` | 0.961 | ~89.8° | 0° |
| `isometricOffAxis1Right` / `4Left` | 1.004 | 0° | 16.5° |
| 其余 41 个 | ~1.000 | 0° | 0° |

### ⚠️ 这一列有取景限制,不能当"是否透视"的证据

**上表的"收敛比"混了两个因素**:预设自带的俯角,**以及**投影类型。
`perspectiveHeroicRightFacing` 是透视预设,但因为自带 pitch 只有 8.7°,
收敛比就接近 1 —— **看起来像平行,实际是透视**。

**要判断投影类型,看 §3 那张表**(显式给了 `lat`,只留投影类型这一个变量)。

### ⚠️ 12 个预设把平面转出了画面

`isometricLeftUp/Down`、`isometricRightUp/Down`、`isometricOffAxis1Left`、
`OffAxis2Right`、`OffAxis3Left`、`OffAxis4Right`、
`perspectiveContrastingLeftFacing/RightFacing`、
`perspectiveHeroicExtremeLeftFacing/RightFacing`

这 12 个**自带的角度太大,平面直接转出取景框**,所以任何基于剪影的量测都失效。
脚本把它们标成 `clipped` 并**拒绝给数**,而不是报一个看着像数据的值。

**用这些预设时要缩小图片或者放大 `fov`**,否则在幻灯片上也会被裁掉。

## 5. 角度反推的校准(这是整个表可信的前提)

反推公式容易写错——我第一版对 62 个预设**全部返回 90.0°**,输出看着像数据。
所以现在**用已知角度的扫描反过来验**:

| 已知 `lat` | 反推 pitch | 残差 |
| --- | --- | --- |
| 330° | 29.66° | 0.0° |
| 315° | 44.46° | −0.2° |
| 300° | 59.40° | −0.3° |
| 285° | 73.67° | −1.0° |

**最大残差 1.0°,跨 45° 范围。** 参考线 `pitch = 29.66 + (330 − lat)` 是**从这四组解出来的**,
不是猜的(我猜错过三次:270、300、240)。

**判据是残差要"平",不是"零"**:常数残差说明参考常数略有偏差;
**递增的残差说明反推本身在漂**,那时 pitch 列就不能用。这个检查每次跑都会打印。

## 6. `lat` / `lon` 各管什么

在 `perspectiveFront` 上扫 `lat × lon`:

| lat | lon | 收敛比 | 压扁度 |
| --- | --- | --- | --- |
| 330° | 0° | 0.901 | 0.864 |
| 315° | 0° | 0.866 | 0.704 |
| 300° | 0° | 0.842 | 0.496 |
| 285° | 0° | 0.828 | 0.255 |
| 330° | 15° | 0.689 | 1.024 |
| 300° | 45° | 1.238 | 1.891 |
| 285° | 45° | 1.857 | 3.505 |

- **`lon = 0` 时形状最规整**(左右对称)。做"躺平的地面"就用 `lon = 0`。
- **`lat` 主要控制压扁度**(0.864 → 0.255),数值越小越扁。
- **`lon ≥ 15°` 后形状明显不对称**,`lon = 45°` 且 `lat ≤ 300°` 时收敛比甚至 `> 1`,
  说明已经不是一块可读的平面了。

### `rev`:绕视线方向转,不改变透视

| `rev` | 收敛比 | 压扁度 |
| --- | --- | --- |
| 0° | 0.866 | 0.704 |
| 90° | 1.000 | 1.537 |
| 180° | 1.155 | 0.704 |
| 350° | 1.040 | 0.853 |

`rev` 把平面在屏幕内转动,所以"上下边的宽度比"这个量测在 `rev ≠ 0` 时**失去意义**
(转到 90° 时上下边变成了左右边)。**要做平面构图就用 `rev = 0`。**

## 7. `fov` 是**透视强度的连续旋钮**

| `fov` | 收敛比 | 压扁度 |
| --- | --- | --- |
| 0° | 1.000 | 0.701 |
| 15° | 0.955 | 0.704 |
| 45° | 0.866 | 0.704 |
| 90° | 0.708 | 0.704 |
| 120° | 0.540 | 0.705 |

- **单调、可预测**,而且**几乎不影响压扁度** ——
  即 **`fov` 单独控制"透视有多强",`lat` 控制"俯角有多斜",两者可分别调。**
- `fov = 0` 时收敛比 1.000,**等价于平行投影**。
- 规范说 `fov` 对非透视相机被忽略,实测确认(`orthographicFront` 下任何 `fov` 都是 1.000)。

> ⚠️ 网上常见的转述会写成"`fov` 被忽略",那会让人以为它没用。
> **[MS-OI29500] 的原话是"对非透视相机被忽略"**,而在透视相机上它是最好用的旋钮。

---

## 8. `zoom` 不影响透视,只缩放

| `zoom` | 收敛比 | 压扁度 |
| --- | --- | --- |
| 25000 | 0.851 | 0.693 |
| 50000 | 0.861 | 0.695 |
| 100000(默认) | 0.866 | 0.704 |

收敛比在 0.851~0.866 之间波动(量测噪声),**投影几何不变**。
`zoom` 放大到一定程度形状会**超出画面**,此时任何剪影量测失效(见 §9)。

## 9. ⚠️ 量测的有效范围(这条比数字本身重要)

**剪影一旦触及画面边缘,量出来的就不是形状,是画面边界。**

这个坑我踩过:`zoom = 200000` 时最初量到收敛比 **1.000**,
看起来像"zoom 把投影变成平行"。实际是**板子放大到出画**,
`near_w == far_w == 图像宽`。**同样的假象当时静默污染了整个 `fov` 扫描。**

**所以脚本现在会检测剪影是否接触边缘,接触就标 `clipped` 并拒绝给数。**

**读表容差**:理想平行投影收敛比是 1.000,但像素级量测有噪声,
实测正交相机落在 **0.85~1.00**。**判据是"接近 1"而不是"等于 1"。**

**可比性**:收敛比是两个投影边长之比,**绝对值依赖探针几何**。
只和同一探针测的数比;探针参数存在 `meta.probe_geometry` 里。

## 10. 怎么用这张表

**做"躺平的地面"(参考图那个效果):**

```xml
<a:camera prst="perspectiveFront" fov="5400000">   <!-- fov 90°,透视中等 -->
  <a:rot lat="18900000" lon="0" rev="0"/>          <!-- lat 315°,俯角约 45° -->
</a:camera>
```

- `prst` 必须选 `perspective*` 或 `legacyPerspective*`,否则**永远出不来透视**
- `lat = 315°`,**不要写 `-45°`**(负数毁文件)
- `lon = 0`、`rev = 0`,保持正视对称
- 想要**透视更强**就加大 `fov`,不要靠 `lat` 硬压(那会连带压扁)

**判断"躺下了没有":量远边是不是明显比近边窄。**
不要看"像不像平行四边形" —— **平行投影的矩形在任何角度都像**,这个判据零区分力,
我因此选错过一次姿态。

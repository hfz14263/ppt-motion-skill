# 切换的形态层：每个效果看起来在做什么

> 一句话：**`transitions.md` 说"这个名字是什么元素"，`transition-model.md` 说"这套机制怎么运作"，
> 本文件说"观众眼睛看到的是什么运动"。**

三层的关系，以及各自回答不了什么：

| 层 | 文件 | 回答 | 回答不了 |
| --- | --- | --- | --- |
| 名字 | [`transitions.md`](transitions.md) | 界面名 → 写出的 XML | 看到的是什么 |
| 机制 | [`transition-model.md`](transition-model.md) | 挂哪页 / 几个槽位 / 时长听谁 | 具体效果长什么样 |
| **形态** | **本文件** | **运动方向、对称性、推进方式** | **该不该用（见 [`motion-design-spec.md`](motion-design-spec.md)）** |

**⚠️ 这一层的数字来自渲染帧的**统计剖面**，不是逐帧肉眼比对。** 它能可靠回答
"有没有方向、往哪边、是整页动还是局部动"，**不能**回答"好不好看"。所有判定都配了
能推翻它的标定（见 §四），因为这一层踩过的坑比前两层都多。

## 一、先说结论：把 48 个效果按「看起来在做什么」分成 7 族

这不是按界面分组（细微/华丽/动态内容），而是按**运动的性质**分。同族的效果可以互换，
跨族的不行 —— 这是选择时的第一个判断。

| 族 | 在做什么 | 成员 | 该用什么指标认它 |
| --- | --- | --- | --- |
| **硬切** | 瞬间替换，无过程 | `cut` | 活跃帧 = 0 |
| **整页平移** | 整张画面滑走/滑入 | `push` `pan` `switch` `page_curl` `window` | **位移**（相位相关） |
| **方向揭示** | 一条**前沿**扫过画面 | `wipe` `cover` `uncover` `box` `shape` `wind` `glitter` `origami` `peel_off` `checkerboard` `comb` `airplane` `crush` `curtains` `drape` `fall_over` `prestige` `reveal` `honeycomb` | **变化漂移**（差异重心轨迹） |
| **中心扩散** | 从中间向四周（或反向） | `split` `ripple` `fade` `dissolve` `randombar` `morph` | **径向剖面** |
| **旋转** | 绕中心扫过一圈 | `clock` | **角度轨迹**（扇区扫过序，见 §八） |
| **均匀淡变** | 整幅同时变化，无方向 | `flash` | 覆盖率高 + 漂移≈0 |
| **随机** | **每次放映都不同** | `random` | 不可测（见 §三） |

**"方向揭示"是最大的一族（19 个）**，也是商务场景里最该谨慎用的一族 —— 它们全都
带方向性，方向会与阅读顺序、时间流向发生关系。

> ⚠️ **`clock` 原本被错归到「中心扩散」** —— 因为旋转的径向剖面和中心扩散几乎一样，
> 而前三个指标看不见旋转。**这是用户目视发现的**，修正过程见 §三之补 与 §八。

## 二、四个指标，各自能看见什么

这一层不能用"整帧均值"判断（`transition-model.md` §七记了两次踩坑）。用的是三个
**互补**的统计量，任何一个单独都不够：

### 指标 A：变化漂移（差异重心轨迹）

每一帧算出"哪里在变"的重心，看这个重心在过渡期间**往哪走**。

- **看得见**：`wipe` `cover` `uncover` 这类有前沿扫过的效果。
- **看不见**：`push` 这种整页平移 —— 每一列都在同等变化，重心原地不动。

实测（`wipe`，30fps，差异列重心 0=最左 1=最右）：

```
帧 65: 0.871    帧 71: 0.677    帧 77: 0.462    帧 80: 0.425
```

重心从右侧一路降到中间偏左 → **前沿从右向左**。这是 `wipe` 的默认方向。

### 指标 B：累积位移（逐帧相位相关）

对过渡窗口内**每一对相邻帧**做相位相关，把位移**累加**。

- **看得见**：`push` `pan` 这类整页滑动。
- **看不见**：`wipe` 这种只有一条边在动的 —— 全局相位相关读不到。

⚠️ **不能用首尾两帧做相位相关。** 对滑入类效果，首尾两帧都是"运动中途"的样子，
互相很像 → 净位移读成 0。实测 `push` 首尾对比得 0，逐帧累加得 −4~−5px/帧。
**这是本层第一个 bug。**

### 指标 C：径向剖面（中心 → 外）

把平均差异图按半径分环，看能量集中在哪里。

- **看得见**：`fade` `split` 这类中心/环形分布的。
- **看不见**：`wipe` `push` —— 它们的剖面和 `fade` **几乎一样**（见 §四的教训）。

### 指标 D：局域化（覆盖率 + 峰均比 + 带漂移）

**只在探测 deck 2 上有意义**（§四解释为什么需要第二个 deck）。它回答：

- 差异是**铺满全屏**（覆盖率接近 1，`push`/`pan` = 0.96–0.97）还是**集中在一条带**（≈0.4）；
- 带的重心**有没有整体漂移**（`band_travel`）。`wipe` = **−0.747**（大幅漂移），
  `fade` = 0.015、`split` = −0.015（几乎不漂）。

## 三、`random` 是唯一测不了的效果，原因是它自己

`random` 在两次探测里给出了**不同的**结果（deck1 = `t->b centre-out`，deck2 = `r->l`）。

核对 XML：`clock` 写 `<p:wheel spokes="1"/>`，`random` 写 `<p:random/>`。
两个 mp4 **文件大小完全相同（186,629 字节）但 md5 不同**。

> **`<p:random/>` 每次放映随机挑一个效果。** 所以"`random` 的形态"这个问题本身
> 没有稳定答案 —— 不是测不出来，是它不存在。
>
> **实践含义**：用 `random` 就无法保证任何观感一致性。商务场合不要用。

### 三之补：但"它这次挑了什么"是可以测的

用户看到 `random` 表现为"从 y 轴一条线顺时针扫过、最后回到 y 轴"。
这话**完全正确**，只不过那描述的是它**那一次抽中的效果**，不是 `random` 自己的形态。

把它和 `clock` 放一起比，角度轨迹**逐帧相同**：

```
random  285 → 75 → 60 → 45 → 30 → 15 → 0 → 345 → 330 → 315 → 285 → ... → 90
clock   285 → 75 → 60 → 45 → 30 → 15 → 0 → 345 → 330 → 315 → 285 → ... → 90
```

→ 这一次 `random` 抽中的就是 wheel（= `clock`）。**印证了 §三：不可测，不是测不出。**

**方法论副产品**：这告诉我们"旋转扫过"需要一个**独立的指标** ——
按 24 个扇区统计变化能量的角度轨迹。前四个指标（位移/漂移/径向/局部性）
都**看不见旋转**（旋转的径向剖面和中心扩散几乎一样）。详见 §八。

## 四、这一层踩过的坑（比前两层都多）

### 坑 1：探测 deck 每格都变色 → 方向被平均掉

第一版 deck 两页的网格**每一格都改了颜色**。结果差异图近似均匀，
`push`（最典型的整页位移）被测成 `stationary`。

**修法**：网格两页**完全相同**（当静态参照系），只让**一个标记**在两页之间移动 + 变色。

### 坑 2：编码器噪声被当成过渡

H.264 在**本该完全相同的**帧之间留下孤立噪声尖峰。实测在静止网格上：
单帧能量 84–170。而弱过渡的峰值可能只有 ~800 —— **峰值的 10% 是 80，正落在噪声带里**。

后果：`wipe` / `fade` 的"活跃窗口"被撑到 **120 帧**（整个停留时长）。

**修法**：先按显著性取阈，再要求**连续性** —— 真实过渡是**连续的一段**，
噪声是**孤立单帧**。只保留 ≥3 帧的连续段，取其中能量最大的那段。
修完 `wipe` 从 120 帧收敛到 15 帧，`cut` 正确变成 0 帧。

### 坑 3：首尾帧做相位相关 → 整页平移读成 0

见 §二 指标 B。**修法**：逐帧累加。

### 坑 4（最重要）：一个 deck **分不开全部效果**

即使修完前三个坑，`fade` / `wipe` / `dissolve` / `split` / `shape` / `randombar` / `box`
的径向剖面仍然**几乎完全一样**：

```
fade      [1.0, 0.15, 0.05, 0.11, 0.04, 0.0, 0.0]
wipe      [1.0, 0.15, 0.05, 0.12, 0.04, 0.0, 0.0]
dissolve  [1.0, 0.15, 0.05, 0.11, 0.04, 0.0, 0.0]
```

**根因**：deck 1 里两页之间**只有中心的圆在变**，所以不论什么效果，
差异都集中在中心。它们的差别在**变化怎么扩散**，不在**变化在哪里**。

**修法**：**第二个探测 deck**（`shapedeck2`）—— 两页都是**满屏随机噪点纹理**
（同样的平均亮度，不同的空间图案）。这样：

| 效果 | deck2 上的表现 | 判定 |
| --- | --- | --- |
| `wipe` | 前沿逐区暴露新纹理 → 差异成**移动的带** | `band_travel` = **−0.747** |
| `fade` | 整幅同时变化 → 差异**均匀** | `band_travel` = **0.015** |
| `split` | 从中心向两侧打开 → 重心**向外** | `band_travel` = **−0.015** |
| `push` | 整页滑走 → **覆盖率 0.957** + 有位移 | `coverage` = 0.957 |

> **结论（这一层最有用的一条）**：**没有一个探测 deck 能同时看清所有效果。**
> 想知道"变化在哪"和想知道"变化怎么扩散"，需要**两种不同的画**。
> 这跟前两层的结论是同构的：**问题的性质决定要用什么仪器，不能一把尺子量到底。**

### 坑 5：别把"我测不出来"写成"它没有方向"

`honeycomb` / `shred` / `doors` / `window` 在第一轮分类里被归进"整页平移"，
但它们的**位移指标是小幅噪声级**（不是 `push` 那种稳定的 −4~−5px/帧）。

它们真实的样子是**内部纹理在变**（蜂巢格子逐个翻转、碎片重组），
既不是平移也不是均匀淡变。**本层对这四个给不出可靠的方向结论**，如实记在 §五。

### 表里两处「不一致」，是真实分歧不是错误

- **`box` / `shape`**：deck1 判 `l→r sweep`，deck2 判 `stationary`。
  这两个效果在**中心有标记的 deck** 上像扫描，在**满屏噪点的 deck** 上像原地变化。
  合理推断：它们是**从中心展开的框/圆**，在两种画面下呈现不同。
- **`flip`**：方向 `l→r` 但位移 `r→l`。翻转是**绕轴旋转**，两个指标各看到一半。

**这两处不合并、不取平均** —— 分歧本身是信息。

## 六、⚠️ `morph` 不适用本表

`morph` 在表里被判成 `l→r 中心扩散`，但**这个判定对它没有意义**。

原因：其余效果补间的是**两张画**，所以"运动形态"是效果自带的、与内容无关的。
`morph` 补间的是**对象之间的对应关系** —— 它的运动形态**由你放进去的几何决定**，
不由效果决定。

> 我的探测 deck 里只有"网格 + 一个移动的圆"，所以量到的就是"那个圆从这走到那"。
> 换个内容，morph 的形态就完全不同。
>
> **`morph` 的形态 = 你设计的两个端点之差。** 这正好回到
> [`transition-model.md`](transition-model.md) §五那张对比表：只有 morph 需要你操心内容。

## 七、复现这套测量

```bash
# 1. 造两种探测 deck

# 2. 用 PowerPoint 逐份渲染（40 秒左右一份）

# 3. 分析
python scripts/build_transition_table.py shapes C:/t1w/shape2 --out C:/t1w/shape2/shapes.json
python scripts/build_transition_table.py shapes C:/t1w/shape3 --out C:/t1w/shape3/shapes.json

# 4. 单份细看
python scripts/build_transition_table.py shapeanalyze C:/t1w/shape2/wipe.mp4 \
                                                C:/t1w/shape2/wipe.manifest.json
```

## 八、⚠️ 第四类指标：旋转 —— 前三个都看不见它

**这是被用户看出来的。** 他说 `random` 是"从 y 轴一条线顺时针扫过、最后回到 y 轴"。
一查，那其实是他抽中的 `clock`（见 §三之补），但**更重要的是：我的三个指标都没能
把这事说清楚** —— 文档里 `clock` 当时被归到「中心扩散」，方向记成 `t→b`，**两条都是错的**。

### 为什么前三个指标看不见旋转

| 指标 | 对旋转的反应 | 为什么 |
| --- | --- | --- |
| 变化漂移（重心轨迹） | ❌ 原地打转 | 一圈扫下来，重心几乎回到原点，均值≈画面中心 |
| 累积位移（相位相关） | ❌ 读不到 | 不是整页平移 |
| 径向剖面 | ⚠️ 撞车 | 旋转的径向分布**和中心扩散几乎一样**，都从中心向外 |

所以 `clock` 被误判成「中心扩散」+ `t→b` —— 指标没覆盖到的形态，会被**就近塞进**最像的族。

### 第四指标：按角度分扇区，看轨迹

把画面绕中心切成 24 个 15° 扇区，逐帧统计**哪个扇区在变**，得到一条角度轨迹：

```
clock / 本次 random：
帧 62-67   75° → 0°      （自右上顺时针）
帧 68-72   0° → 315°     （过右边）
帧 73-80   285° → 180°   （过多下侧）
帧 81-85   165° → 90°    （回到正上）
```

**判据**：角度**单调递减**（0→345→330…）即顺时针；起点/终点都落在 90°/270°
（y 轴）—— 正是"从 y 轴开始、扫一圈、回到 y 轴"。

> **教训**：每加一类"看的方式"就得问一句 —— **它看不见什么？**
> 三个指标覆盖了平移/扫描/扩散，但**旋转从缝里漏过去了**。
> 漏掉的后果不是"测不出"，是"被错误归到最像的那一族"，这更糟 ——
> 因为它看起来有结论。

### 归入旋转族的效果

`clock`（`<p:wheel spokes="1"/>`）是典型。`random` **抽中 wheel 时**表现相同，
但它本身无稳定形态（§三）。

### 标定：怎么知道这个分析器是对的

`tests/test_transition_table.py` 第 8 组用**合成的**帧序列对表：

- 造一个从左推进的擦除 → 必须判 `l->r`；
- 造一个从右推进的 → 必须判 `r->l`；
- 造一段完全静止的 → 必须判 `none`。

> **第一版这个测试自己是错的**：两个分支生成的帧**完全相同**
> （都是"白色区域从左边长出来"），于是左右两次都判 `l->r`，
> 测试却"通过"了 —— 因为我把期望值也写反了。**测试通过不等于测试有效**，
> 直到我把右侧分支改成"白色从右边长出来"才发现。这个 bug 是测试抓出来的。

## 九、`dir` 换一个值，运动会不会镜像 —— 已实测

前八节量的全是每个效果的**默认**形态（不写 `dir`）。但"`dir` 起什么作用"
是选择层的地基：`transition-choice.md` 整张推荐表都写着"递进要显式写 `dir=l→r`"。
**这个假设此前从未被量过**，只是从属性字面意思推的。

测法：同一效果各做一份 `dir=l` 与 `dir=r` 的 deck（`dirdeck`），渲染后配对比较
（`dirmirror`）。

### 结论：4 个推荐效果全部镜像，`curtains` 确为对称

| 效果 | 判定 | 依据 | 数据 |
| --- | --- | --- | --- |
| `push` | **镜像** | 累积位移 | `tx` = **-1.004 / +1.009**（反向，距离几乎相等） |
| `wipe` | **镜像** | 重心轨迹 | 轨迹相关系数 r = **-0.994** |
| `uncover` | **镜像** | 重心轨迹 | r = **-0.986** |
| `cover` | **镜像** | 重心轨迹 | r = **-0.978** |
| `curtains` | **不镜像** | 重心轨迹 | r = **+1.000**，两个方向 `tx` 均 **0.000** |

r 接近 **-1** = 两个方向逐帧对着走；接近 **+1** = 两个方向完全一样（`dir` 被忽略）。

### ⚠️ 又是同一个教训：单路仪器必有一族看不见

判 `push` 时第一版判据给出 **`ambiguous`**，看起来像"push 的行为很怪"。**不是。**
是仪器选错了：

| 仪器 | 看得见 | 看不见 | 对 push 的读数 |
| --- | --- | --- | --- |
| 变化重心（`cx_trace`） | 揭示类前沿（wipe/cover/uncover） | **整页平移** | `dx` = **0.011** → 读成「静止」 |
| 累积位移（`tx`） | 整页移动（push） | 扫描类（总质量位移≈0） | `tx` = **±1.0** → 一目了然 |

整页平移时**每一列的变化量相等，变化重心根本不动** —— 这是坑 3 的另一种表现。
所以镜像判定**两路并行，取有信号的那路**。

> 这与 §八（旋转躲过前三类指标）是同一条规律的第**二**次出现：
> **每个指标都有一族看不见的东西，而看不见时不报错、只给错答案。**
> 第一路判 push 为 `ambiguous` 时没有任何异常，结果就是错的。

### 为什么 `curtains` 是 +1.000

`curtains` 是**左右对称对开**（§五表），两个方向本来就没有区别 —— 加 `dir`
不改变任何东西，所以两条轨迹**逐帧相同**。这不是"测不出"，是"它确实没有方向"。
（区别很重要：§五 的坑 5 就在讲别把"我测不出来"写成"它没有方向"。
这里两个方向都测出来了，且**测出来就是一样**。）

### 标定：怎么知道这个判据是对的

`tests/test_transition_table.py` 第 12 组用**合成的**帧序列对表：

- 左→右的扫过 vs 右→左的扫过 → 必须判 `mirror`（r ≤ -0.7）；
- 同一序列**与它自己** → 必须**不**判 `mirror`（负向对照：少了它，
  "永远返回 mirror"的坏实现也能骗过第一条）；
- 完全静止 → 必须判 `no-motion`（数据不足时不许硬给结论）。

# 视频动效分析的实测能力边界

本文件记录 `scripts/analyze_video.py` 在**已知答案的样本**上测出来的准确度。
不是理论分析，是实跑数据。改动分析器前请先复现这里的结论。

## 标定样本

`scripts/make_calibration.ps1` 生成，真值硬编码：

- 第一页：三个圆依次渐入，**1.5s / 1.0s / 0.5s**，两两间隔 **0.5s**（靠 `TriggerDelayTime` 制造）
- 第二页：文本框，用于验证分页切分
- 导出：PowerPoint `CreateVideo`，1280×720 @ 30fps，质量档 85
- 三个圆**故意用纯黑**（高对比度）—— 见下面第 2 条，低对比度测不出来

## 实测准确度

| 动画 | 真值起点 | 测得起点 | 起点误差 | 真值时长 | 测得时长 | 时长误差 |
| --- | --- | --- | --- | --- | --- | --- |
| 渐入 1 | 0.00s | 0.10s | +0.10s | 1.5s | 1.52s | **+0.02s** |
| 渐入 2 | 2.00s | 1.98s | −0.02s | 1.0s | 1.12s | **+0.12s** |
| 渐入 3 | 3.50s | 3.56s | +0.06s | 0.5s | 0.66s | **+0.16s** |

**起点误差 ≤0.10s，时长误差 +0.02~+0.16s**（越短越容易高估，因为尾部要等帧间差分回落）。
这个精度足够支撑设计规范 §2 的时长阶梯判断（阶梯间隔是 0.2s 级别）。

## 关键实现结论

### 1. 信号必须用「最大差分」，不能用块均值或低阈值计数

在**完全静止**的画面上，H.264 编码噪声让 `diff>2` 的像素占比恒为 **13%**，块均值稳定在 0.5–0.9，
与真实动画无法区分。实测对比：

| 信号 | 静止帧 | 1.5s 渐入过程 | 可用性 |
| --- | --- | --- | --- |
| 块均值 / `diff>2` 计数 | 0.52–0.91 / 13% | 与静止无异 | ❌ |
| `diff>8` 计数 | 0 | 断续 0.12 | ⚠️ |
| **最大差分 `diff.max()`** | 0–9 | 单调升到 57–64 | ✅ |

高对比度样本上，静止段的最大差分**恰好为 0**，噪声底干净 —— 这是能测准的原因。

### 2. 低对比度 + 低码率 = 测不出来（最硬的边界）

同一份标定里，圆若是低对比度颜色（与白底差得少），逐帧差分峰值只有 15–21，
与噪声底（15–21）完全重叠，**无论怎么调参都测不到**。

可测性 ∝ 元素与背景的对比度 × 视频码率。PowerPoint 自带 `CreateVideo` 码率偏低，
对细微动画不够。**要测细微动效，必须用高码率录屏（≥5 Mbps）。**

### 3. 首尾相接的动画会合并成一段（这是对的，别误判为 bug）

用 `afterEffect` 链式触发的连续动画（没有 delay）在视频里是**一段连续运动**。
第一次标定就踩了这个坑：三个渐入 1.5+1.0+0.5 首尾相接，分析器正确报成**一段 3.13s**，
而当时误以为它把三个动画合并了。加了真实间隔后才分离出三条。

**推论**：结果里"一个较长的 burst"可能实际是多个连续动画，需结合内容判断。

### 4. 幻灯片切换要单独识别

硬切在单帧内产生满量程差分（峰值可达 255）。实测里这些事件**每次只有 0.07–0.13s**。
分析器把 `duration <= 5 帧` 或 `snr < 1.6` 的事件标为 `cut / encoder artifact (ignore)`。
排除后真实动画落在 **0.17–2.08s**，与注入设定相符。

## 能稳定读出 / 读不出的东西

| 量 | 可信度 | 说明 |
| --- | --- | --- |
| 动效时刻、顺序 | ✅ 高（±0.10s） | |
| 动效时长 | ✅ 中高（+0.02~+0.16s） | 系统性偏长，短动画误差比例更大 |
| 间隔 / 节奏 | ✅ 高 | |
| 变化区域位置（bbox） | ✅ 中高 | |
| 循环 / 往复 | ⚠️ 中 | 判据是质点反向次数，慢速渐入会被误判（见下） |
| **效果家族分类** | ⚠️ **低** | 见「已知误判」 |
| **真实效果名** | ❌ 不可能 | 像素里没有这个信息 |

### 已知误判（必须知道）

标定里第 1 条（1.5s 渐入）被误判为 `loop / oscillate`：慢速渐入时变化区掩膜的
质点抖动剧烈（实测 x 方向反向 **25 次**），而面积增长只有 1.2 倍，触发了循环判据。
第 2、3 条（增长 1146x / 7.2x）分类正确。

**结论：把 `probable` 当线索，不要当结论。** 时长和顺序可靠，效果类型需要人判断。

## 建议的输入

| 输入 | 精度 | 建议 |
| --- | --- | --- |
| **`.pptx` 源文件** | **零误差** | 首选。`motion.py inspect` 直读 `presetID / duration / trigger / 顺序` |
| 高码率录屏（≥5 Mbps） | 高 | 拿不到 pptx 时的最佳选择 |
| PowerPoint 导出的 MP4 | 中 | 能测大动作与节奏，细微动效不可靠 |
| 低码率 / 二次压缩视频 | 低 | 只能看个大概 |

## 复现方法

```powershell
# 1. 生成已知答案的标定 deck + 视频
powershell -NoProfile -File scripts/make_calibration.ps1
# 2. 跑分析器
python scripts/analyze_video.py --video tests/calib/calib.mp4 --json
# 3. 看原始信号
python scripts/analyze_video.py --video tests/calib/calib.mp4 --out out
#    out/motion-analysis.json 的 timeline.activity 就是逐帧最大差分
```

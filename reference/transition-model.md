# 切换的心智模型

> 一句话：**一次页面切换不是一个「效果」，是一次「进入」；它挂在被进入的那一页上。**

`reference/transitions.md` 回答「界面上那 48 个名字分别对应什么 XML」——那是**数据表**。
本文件回答「这些东西该怎么用」——那是**机制层**。五条模型，每一条都能被推翻，
每一条都是本机渲染出来的帧给的答案，不是从文档里读来的。

| 模型 | 一句话 | 能解释什么直觉误解 |
| --- | --- | --- |
| [一、切换挂在终点页](#m1) | 写在哪页，管的就是「进入哪页」 | 「写在这页为什么动的是上一次翻页」 |
| [二、只有一个槽位](#m2) | 一次 `<p:transition>` 只能装一个东西 | 「为什么形状形变和整页位移不能同时」 |
| [三、时长只有一个真相](#m3) | `p14:dur` 压过 `spd`；`spd` 是降级世界唯一的旋钮 | 「为什么有的环境里时长全是中等」 |
| [四、它看不见形状](#m4) | `<p:transition>` 在形状容器之外 | 「为什么想要『某一个东西动』就不能用切换」 |
| [五、切换与动画串行](#m5) | 动画**等**切换演完才开始；延迟 ≈ 切换时长 + 133 ms | 「为什么挂了切换后入场动画像慢了半拍」 |

## 一、切换挂在终点页上

<a id="m1"></a>

### 这句话跟 morph 那句话是同一句

当初总结平滑，说的是：

> 对一页 PPT 复制出两页 —— 第 1 页是**初始状态**，第 2 页是**预期状态**，
> 两页不同的部分被逐帧补间。**两页是一个变化的两个端点。**

把「复制出两页」换成「本来就有相邻两页」，这句话对全部 48 个切换都成立：

| 机制 | 变化的两个端点 | 起点从哪来 | 终点从哪来 | 中间靠谁补 |
| --- | --- | --- | --- | --- |
| **morph** | 复制出的第 1 页 / 第 2 页 | 你手写 | 你手写（改几何／相机） | `<p159:morph/>` |
| **其余 47 个** | 上一页 / 这一页 | 现成的，上一页长什么样就从什么样过来 | 也是现成的，你只在这页写一根 XML | 47 个之一 |

差别只有一个：**普通切换的起点不用你管**（所以数据表是「只在一页上写」就够），
**morph 的起点必须你亲手设计**（所以 morph 的规矩才是「两页都要写」）。

### 断言与判伪设计

两个互斥的说法：

- **A**：`<p:transition>` 写在第 N 页 → 动的是 **进入第 N 页**（N-1 → N）
- **非 A**：写在第 N 页 → 动的是 **离开第 N 页**（N → N+1）

读 XML 分不出这两种：**两种说法下「切换在第 N 页上」都成立**。只有渲染出来的帧能分。
所以做了一个能推翻 A 的 deck —— **三页，只有第 2 页写 `<p:push dir="u"/>`，800 ms**：

| 说法 | 预测第 1 个页边界（1→2） | 预测第 2 个页边界（2→3） |
| --- | --- | --- |
| A | 多帧补间（burst） | 单帧硬切 |
| 非 A | 单帧硬切 | 多帧补间（burst） |

### 实测（anchor.mp4，30 fps，每页停留 2 s）

```
帧区间        帧数   毫秒    判定          落在
62–85        24     800     过渡 burst   边界 1（第1页→第2页）
89–89         1      33     硬切         （推送末帧收尾）
148–148       1      33     硬切         边界 2（第2页→第3页）
```

burst 落在**进入第 2 页**的那一次，24 帧 = 800 ms，与写进去的 `p14:dur` 一帧不差。
第 2→3 边界只有一帧跳变。**非 A 被排除。**

同一份 deck 改成每页停留 5 s 重渲染，burst 仍是 **24 帧 / 800 ms**，位置顺延到 153–176。
**过渡时长跟页面停留是两笔独立的钱** —— 「三、时长只有一个真相」还会把这条量化。

### 由模型 ① 直接推出的三条

**推论 1｜写错页 = 效果往前挪一个边界。**
想让第 5→6 页动画化，写在第 5 页上，得到的是：5→6 硬切，而 4→5 意外地动了起来。
本项目里决定这件事的位置就是 spec 的 `slides[].page`（`scripts/motion.py` 的
`normalize_spec`）—— **那一页是终点页，不是出发页。**

**推论 2｜第 1 页没有前驱，它的切换只用在放映起步那一刻。**
这不是「写错会被忽略」，是真的被用上了 —— 只是那次特殊的页边界是**从黑场进入开场**。
实测（`first.pptx`，两页，只有第 1 页写 `<p:wipe dir="l"/>` 800 ms）：

```
帧区间        帧数   毫秒    判定          落在
2–24         23     767     过渡 burst   放映起步（自黑场）
87–87         1      33     硬切         真正的第1→2边界
```

而且它是**真的擦除**，不是冒充的淡入。第 8 帧逐列灰度：

```
帧  8 列灰度(左→右):  0.0  0.0  0.0  2.0  11.7  32.0  54.7  77.7
```

右边先亮、边界向左推进 —— 与 `dir="l"` 一致。**别靠「整体均值」判断 wipe 长什么样**，
见 [§测量坑](#trap)。

**推论 3｜这解释了为什么 morph 的规矩是「两页都要加」。**
`com-pitfalls` §20.4 一开始写「只给第 2 页加」，后来被实测纠正。用模型 ① 看，
那条纠正不需要背：第 2 页的 morph 负责"进入第 2 页"；第 1 页也带 morph，
是因为第 1 页自己也要被**进入**（从它上一页过来），两页属于同一条链。

## 二、一个 `<p:transition>` 只有一个槽位

<a id="m2"></a>

### 实测：装两个子元素 → 整份文件被拒开

| deck | `<p:transition>` 里放了什么 | PowerPoint 的反应 |
| --- | --- | --- |
| `twochild.pptx` | `<p:push dir="u"/>` **+** `<p159:morph option="byObject"/>` | **PowerPoint could not open the file**（整份） |
| `twochild_core.pptx` | `<p:push dir="u"/>` **+** `<p:wipe dir="l"/>` | **同上**（整份） |

不是静默丢一个，不是只留第一个 —— 是**整份文件打不开**。跟「缺 `dir`」那次是同一类失败：
单个非法切换子元素会让 PowerPoint 拒开整份文件，所以这类候选必须**一个一份 deck** 去探。

### 由此决定的架构

「形状怎么形变」和「整页怎么过去」不能同时表达 —— 它们抢同一个槽位。所以本项目的两套机制
不是啰嗦，是被这件事逼出来的：

| 想表达的东西 | 走哪套 | 写在 XML 的哪里 |
| --- | --- | --- |
| 这一页被**怎样换掉**（整体关系） | 页面切换，占那唯一一个槽位 | `<p:sld>/<p:transition>` |
| 这一页里**某个东西怎么动**（个体行为） | 页内动画，数目不限 | `<p:sld>/<p:timing>` |

⚠️ **两套机制在结构上平行，在时间上是串行的** —— 切换演完，页内动画才开始。
「正交」只适用于「各自能装几个」，不适用于「什么时候演」。见 [五、同页的切换与动画不是正交的](#m5)。

**降级链条也只是一条直线**：`mc:Choice` 里一个、`mc:Fallback` 里一个，
不是两条并行叠加。「首选 morph，不支持就 fade」是自然的；
想要「既 morph 又 push」从结构上就不成立。

<p align="right"><sub>来源 com-pitfalls §40、§43</sub></p>

## 三、时长只有一个真相，是毫秒的那个

<a id="m3"></a>

`<p:transition>` 上有两个都像「时长」的东西：`spd="slow|med|fast"` 和 `p14:dur="800"`。
**它们是同一个量的两种写法**，而谁能压过谁必须量，不能猜。

### 实测：让它俩打架（duel.pptx，每页停留 2 s）

| 页 | 写进去的 | 若 `p14:dur` 赢 | 若 `spd` 赢 | 实测 burst |
| --- | --- | --- | --- | --- |
| 第 2 页 | `spd="slow"` + `p14:dur="200"` | ~6 帧 | ~60 帧 | **62–67，6 帧 = 200 ms** ✅ |
| 第 3 页 | `spd="fast"` + `p14:dur="1500"` | ~45 帧 | ~15 帧 | **132–175，44 帧 = 1467 ms** ✅ |

每页停留改成 5 s 后：6 帧 / 43 帧 —— **没变**。

> **`p14:dur`（毫秒）赢，`spd` 在 Choice 分支里被忽略。**

### 那 `spd` 为什么还必须写？

因为 **`mc:Fallback` 里没有 `p14:dur`，也不可能有** —— 那是 2010 年的属性，
而 Fallback 的世界正是「没有 2010 扩展」的那个世界。所以在 WPS / 旧版 PowerPoint /
在线预览里，**唯一说话的就是 `spd`**。

于是「慢 / 中 / 快」到底值多少毫秒，就成了降级世界的实际时长量出来的：`notch.pptx`，
同一个 `<p:dissolve/>`，只写 `spd`、不写 `p14:dur`：

| `spd` | 实测 burst（2 s 停留） | 实测 burst（5 s 停留） | 结论 |
| --- | --- | --- | --- |
| `slow` | 30 帧 = 1000 ms | 30 帧 = 1000 ms | **≈ 1.0 s** |
| `med` | 22 帧 = 733 ms | 23 帧 = 767 ms | **≈ 0.77 s** |
| `fast` | 14 帧 = 467 ms | 15 帧 = 500 ms | **≈ 0.5 s** |

（不是界面上传说的 3 s / 2 s / 1 s。以本机实测为准，环境见文末「复现这套测量」。）

### ⚠️ PowerPoint 会自己重算 Choice 分支的 `spd`

这一条值得单独记，因为**它看起来像「我们写错了」而其实不是**：

| 写入 | `mc:Choice` 往返后 | `p14:dur` 往返后 | 判定 |
| --- | --- | --- | --- |
| `spd="med"` + `dur="800"` | `spd="slow"` | `800` ✅ 没变 | PowerPoint 把 0.8 s 归到最近的档位 |
| `spd="med"` + `dur="600"` | `spd="med"` | `600` ✅ | 落在同一档，看不出变化 |
| `spd="slow"` + `dur="900"` | `spd="slow"` | `900` ✅ | 同上 |

> **毫秒始终没动**，动的是那个粗档位。所以往返后看到 `spd` 变化，
> **不代表时长丢了** —— 真正的时长在 `p14:dur` 里，它一帧不差。

同一份 deck 用 COM 读回 `SlideShowTransition.Duration`，得到 **0.8 / 0.6 / 0.7 / 0.9 秒**
与写入完全一致，可以交叉验证这一点。

### 落到代码上

`spd` 按 `duration` 就近取档（边界：≤633 → `fast`，634–883 → `med`，≥884 → `slow`；
显式 `speed=` 优先）。这样两个分支讲的是同一个故事：

| `duration` | Choice 分支 | Fallback 分支 |
| --- | --- | --- |
| 0.3 s | `spd="fast" p14:dur="300"` | `spd="fast"`（≈0.5 s） |
| 0.7 s（默认） | `spd="med" p14:dur="700"` | `spd="med"`（≈0.77 s） |
| 1.5 s | `spd="slow" p14:dur="1500"` | `spd="slow"`（≈1.0 s） |

在这条规则之前：Choice 分支精确到毫秒没错，Fallback 却一律写死 `spd="med"`，
**在 WPS / 旧版 / 在线预览里，任何时长都会塌回到 ~0.77 s**。

顺带修掉一个更隐蔽的 bug，它只在**同时**给了 `advTm`（自动换页）时才发作：
附加属性是先贴到块上、再跑 `.format()`，于是最后一个 `{spd}` 落进贴过的那一半
（`mc:Choice`），写出 `spd="{spd}"` 这种半成品 —— 而 PowerPoint **照开不误**，
只是把它按自己的规则改成 `slow` 并留着那个 `p14:dur`。现在附加属性与占位符
一起合流，两个分支都会拿到（`fallback` 世界里自动换页同样必须生效）。

这两条都由 `tests/test_transition_table.py` 钉住（取档边界 + 「带 `advTm` 后无占位符残留」）。

## 四、`<p:transition>` 看不见任何形状

<a id="m4"></a>

这不是风格建议，是位置决定的：

```
<p:sld> = <xsd:sequence> ( cSld, clrMapOvr?, transition?, timing?, extLst? )
```

`<p:transition>` 是 `<p:sld>` 的**直接子元素**，和形状容器 `<p:cSld>` **平级**。
它在容器之外，于是**天生看不见容器内任何一个形状**。

推论很直接：

- **切换能表达的只有「这一页被怎样替换掉」** —— 整体关系的陈述。
- **「某一个形状怎么动」只能走 `<p:timing>`** —— 个体行为的陈述。
- 两者**能装几个**互不占用（「整页」只有一个名额，「页内」不限名额），
  但**什么时候演**是串行的 —— 见 [五](#m5)。「正交」这个词只适用于前半句。

一句话的判断规则：**想要表达的是页与页之间的关系，用切换；
想要表达的是页里某个东西的行为，用动画。**

<p align="right"><sub>来源 reference/architecture.md、reference/mso-primitives.md §12</sub></p>

## 五、同页的切换与动画不是正交的 —— 动画会**等**切换演完

<a id="m5"></a>

上一节说「两者正交，互不占用，可以同时存在于一页」。这半句**只对了一半**，
而错的那一半正好是最容易被当成"设计自由"的那一半。

### 已被推翻的旧断言

`transition-model.md` 的前几版在三个地方写了同一句话：

> 「页内个体行为走 `<p:timing>`，**与切换正交，不限名额**」

其中「不限名额」是真的（一页可以挂任意多个 `<p:timing>` 效果），
但「正交」是**推断出来的**，不是量出来的 —— 推断的依据是「它们写在不同的 XML 槽位上」。
这恰好是本项目反复反对的那种推理：**位置不同不等于行为独立。**

### 断言与判伪设计

要同时回答三件事，三件事需要**三种不同的仪器**（这正是本层最值钱的方法论）：

| 问题 | 仪器 | 为什么换仪器 |
| --- | --- | --- |
| 两个块是否都活下来了 | PowerPoint 存回后读 slide XML | 写入的文件里一定有，只有 PowerPoint 的 `Save()` 说得清它认不认 |
| 动画**什么时候**开始 | 逐帧「进入形状的色质量」 | 通用能量指标对淡入**是全盲的**（见下） |
| 两者是否互相改形 | 组合 vs 单独的逐帧像素差 | 只有对照组能回答"是否变形" |

探测 deck 的关键设计：**两页的标记圆盘用不同色相**（第 1 页红、第 2 页蓝），
于是"新页的形状出现了没有"就是一个直接的颜色测量 —— `max(0, B − R)` 的和，
不需要任何阈值启发式。

> ⚠️ **为什么不能用通用能量指标**：一个中灰圆盘淡入到中灰网格上，
> 整帧均值的变化小于 2/255，落在任何合理的阈值之下。实测 `solo_anim` 那一份
> 用能量指标报出 **0 个活跃帧** —— 读起来像"动画根本没跑"。它跑了，
> 是**仪器看不见**。这是本项目第三次踩同一个坑（§47 旋转、§48 整页平移，现在是淡入）。

### 实测结果一：结构上，两个块**都活下来**

9 份 deck 全部往返一次（`scripts/probe_timing_roundtrip.ps1`）：

| deck | 写入 | 存回 | 顺序 |
| --- | --- | --- | --- |
| `both_*`（4 份） | transition + timing | **两者都在** | `transition` 在 `timing` 前 ✅ |
| `solo_anim`（2 份） | 只有 timing | 只有 timing | —— |
| `solo_trans*`（3 份） | 只有 transition | 只有 transition | —— |

**没有任何一份丢掉块。** 所以「不互相吃掉」是真的，
`motion.py` 写出的顺序（`cSld → clrMapOvr → transition → timing`）也就是 PowerPoint 认的顺序。

### 实测结果二：时间上，动画**排队**在切换后面

这一条推翻了旧断言。每份 deck 第 1 页停 2 s（边界固定在 **f60**），
动画固定为**同一个** `fade`、`dur="500"`、`trigger="with"`。
量「新页那个蓝盘什么时候开始出现」：

| deck | 同页的切换 | 动画开始于 | **相对边界延迟** |
| --- | --- | --- | --- |
| `solo_anim` | 无（硬切） | f62 | **+67 ms** |
| `both_fade_short` | `fade` 300 ms | f73 | **+433 ms** |
| `both_push` | `push` 800 ms | f88 | **+933 ms** |
| `both_wipe` | `wipe` 800 ms | f88 | **+933 ms** |
| `both_fade_long` | `fade` 1500 ms | f109 | **+1633 ms** |

**延迟 ≈ 切换时长 + 133 ms。** 四种切换、四种时长，误差都在一帧以内。

而动画自己的长度**一点没变**：五种组合下淡入斜坡都恰好是 **14 帧 ≈ 467 ms**
（写入的 `dur="500"`）。也就是说——**切换改变的是动画的"起点"，
不改变动画的"长度"**。

### 这条规矩的直观读法

一页上的时间轴是这样排的：

```
页边界 ──► [ 切换演完 ] ──► [ 页内动画演完 ] ──► 静止
             ↑ 观众看到新页在动   ↑ 观众才看到新页里的东西入场
```

所以 `trigger: with` 里的 "with" **不是"与切换同时"**，
而是"与**本页动画序列**的第一项同时"。切换根本就不在那个序列里 ——
它在序列**之前**。

### 落到代码上

`motion.py` **不需要改**：它写出的两个块都是合法的、都活下来了、
顺序也对。这条发现约束的是 **spec 的填法**，不是引擎：

- 想要「切换演完立刻入场」→ 什么都不用做，**这本来就是默认行为**。
- 想要「**切换过程中**就有东西在动」→ 做不到。
  页内动画拿不到切换那段时间 —— 想让观众在翻页过程中看到运动，
  只能用切换本身（整页位移／方向揭示），或者用 morph 把运动设计在**页间**。
- **时长要加起来算**：一页的总占用 ≈ `切换时长 + 页内动画总时长`。
  写了 `1.5 s` 的切换又挂了一串入场动画，观众要等 1.5 s 才看见第一个元素 ——
  `motion-design-spec` 的时长上限判据（§6）原本只看动画，现在知道它 **漏算了切换**。

## 五、所以 morph 到底特殊在哪

把四条模型合起来，那句「两页是一个变化的两个端点」可以推广，但要加一句代价说明：

| | 其余 47 个切换 | morph |
| --- | --- | --- |
| 补间的单位 | **两帧图**（上一页的样子 → 这一页的样子） | **对象**（按形状名 / id 跨页配对） |
| 是否读内容 | 不读。两页毫不相干也照演 | 读。没有对应关系就只是消失/出现 |
| 起点要不要设计 | 不要。上一页什么样就什么样 | **要**。同一对象必须在两页都在场 |
| 要写几页 | 一页（终点页） | 两页（同属于一条链） |

**因此「写出来」的工作量差一倍**：普通切换是「在终点页写一根 XML」，
morph 是「先把两个端点亲手做出来，再在两页各写一根」。

这也是 `transitions.md` 那张 48 项表的边界：它能告诉你每个名字对应什么元素，
但**「元素写对了」跟「变化读起来对不对」是两件事** —— 后者只有 morph 需要你操心，
因为只有 morph 会去看你的内容。

<p align="right"><sub>来源 reference/com-pitfalls.md §20.4</sub></p>

## 六、决策表：想表达什么 → 用什么 → 写在哪

| 想表达的事 | 用 | 写在哪 | 注意 |
| --- | --- | --- | --- |
| 两页是同一场景的两种状态 | `morph` | 两页都写，两页都改几何 | 形状名 / id 必须一致 |
| 一个从容的整体过渡，内容无关 | `fade` / `push` / `wipe` | **终点页** `slides[].page` | 别写在出发页 |
| 强调「翻过去了」 | `cover` / `pull` / `split` | 终点页 | `dir` 别漏，漏了整份文件拒开 |
| 全场统一语气 | 同一种切换，全场复用 | 每一页 | 一致性比变化更重要 |
| 页里某个元素的行为 | `<p:timing>` 动画 | 该页 | **数目**不限；但**时间上排在切换之后**（见 §五） |
| 形变 + 位移同时要 | 二选一 | —— | 槽位唯一，见「二、只有一个槽位」 |
| 翻页过程中就有东西在动 | 只能用切换本身 | 终点页 | 页内动画拿不到切换那段时间（§五） |
| 开场从黑场进来要有运镜 | 写在**第 1 页** | 第 1 页 | 只会用在放映起步那一次 |

## 七、测量坑：别用「整帧均值」判断有没有过渡

这一层的所有数字都来自渲染出来的帧，而这一步有两个坑，本项目**先后踩了两次**：

1. **漏检**：`spd="fast" p14:dur="1500"` 的 wipe，逐帧只移动一条边，
   整帧 `absdiff` 均值只有 ~4（噪声阈值 6），**整整 1.5 s 的过渡被判成「没变化」**。
2. **误读**：`first.mp4` 开场那段 wipe，整帧均值从黑到红平滑上升，
   **看起来完全像淡入**；看逐列灰度才发现是有方向的移动边界。

> **结论**：这些探测 deck 是纯色满幅背景，用「整帧平均色有没有变」既灵敏又不会被编码器噪声骗；
> 但要判断**是哪种**运动，必须看**空间剖面**（逐列 / 逐行 / 分块）。

## 八、复现这套测量

```bash
# 1. 造能推翻断言的几份 deck：anchor / first / twochild / twochild_core / duel / notch
python scripts/build_transition_table.py anchordeck C:/t1w/anchor

# 2. 用 PowerPoint 逐份渲染成 MP4，并顺便做 twochild 的拒开测试
powershell -NoProfile -File scripts/probe_anchor.ps1 -Dir C:/t1w/anchor

# 3. 读帧：burst 落在哪个页边界、多少毫秒
python scripts/build_transition_table.py anchors C:/t1w/anchor/anchor.mp4 \
                                                 C:/t1w/anchor/anchor.manifest.json
```

| 命令 | 作用 |
| --- | --- |
| `anchordeck` | 生成判别用的 deck + manifest（含**预测**，便于证伪） |
| `anchors` | 逐帧找「哪里在变、变了多久、离哪个页边界最近」 |
| `probe_anchor.ps1` | 逐份 `CreateVideo` 导出 + 两个子元素的拒开测试 |

**测量环境**：PowerPoint 16.0 build 17928（本机），30 fps，导出分辨率 720p。
时长类数字（800 / 200 / 1467 / 1000 / 767 / 500 ms）在**每页停留 2 s 与 5 s 两种设置下
各测一遍并互相复核**，所以它们描述的是切换本身，不是某次导出的排版。

补两点，免得复算时对不上：

- **`probe_anchor.ps1` 会先把每页的自动换页钉住**（`AdvanceOnTime=-1`、
  `AdvanceTime=$SlideSeconds`），否则 `CreateVideo` 的帧号无从预测。
- **`notch` 那一组用的是 `<p:dissolve/>`**：它是 core 元素、没有必填的 `dir`、
  又不带方向性，能把变量收窄到只剩下「快中慢」本身。换别的 core 元素不影响这套结论，
  但 burst 的**形态**会跟着那个元素走。

`probe_anchor.ps1` 会自动导出目录下**所有** `*.pptx`（`twochild*` 除外，那两个是打开测试），
所以往 `anchordeck` 里加一个新 deck，不用改 ps1。`-SlideSeconds` 可以改每页停留，
用来验证「 burst 长度与停留无关」。

### ⚠️ 别拿「导出视频总帧数」做断言

每一页自己的停留都拿到了：anchor 与 notch 里每一页都是 ~62 帧（2 s @30 fps），
过渡是渲染在两页之间的**独立片段**，不吃前一页也不吃后一页。
但**总时长不稳定**：`anchor.mp4`（3 页 + 0.8 s）应收 ~204 帧，实得 181 帧，最后一页被截短；
`duel.mp4`（3 页 + 1.7 s）却完整没截。**同一导出参数、不同 deck，结尾行为不一致。**

所以：

- ✅ 可断言：**某个页边界上有没有 burst、burst 多少毫秒**（与停留无关，两次复核一致）
- ❌ 不可断言：**第 N 页从第几帧开始、全片多长**

同一类的导出侧限制另见 `reference/video-analysis-limits.md`。

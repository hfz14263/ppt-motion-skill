# 踩坑手册（全部为本机实测）

环境：Windows 10 + Microsoft Office 16.0（Office16）+ Windows PowerShell 5.1 + Python 3.9。

**这一页是目录，不是正文。** 2026-09 它从一份 2000 行 / 51 节的文件拆成了
10 份按主题分的文件 —— 因为"翻一遍找一条坑"已经要滚几十屏，而**查坑的时刻
通常是你已经出错的时候**，那时候最不该付出的成本是找。

拆分的两条硬规矩：

1. **编号不动。** `§44` 永远指"切换的形态"，哪怕它换了文件。全仓库 90+ 处
   引用（`facts/`、`tests/`、各 reference）因此不用改一个字。
   完整编号表：**[`pitfall-map.md`](pitfall-map.md)** ← 看到 `§n` 先来这查。
2. **按"你想干什么"分，不按发现顺序。** 同一类的坑可能编号不相邻。

## 三条最有价值的通用教训

它们不属于任何单一主题，是**反复出现**的：

**① 一个序列型元素只能出现一次。** 存在就替换，不存在才插入。
本项目**所有**损坏文件都是这一条的反面（§31）。

**② "校验通过"不是判据，"真开一遍"才是。**
lxml 只保证 well-formed（§4）；PowerPoint 不接受的东西分三种失效形态 ——
被忽略、打不开、**静默退回默认**（§50）。第三种最贵，因为它不报错。

**③ "我写的不生效" ≠ "这功能不支持"。**
先让 PowerPoint 自己写一遍，比读文档或推理都快（§20 §22）。

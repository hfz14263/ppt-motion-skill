## 28. 把"参数 → 渲染结果"当作待测对象，而不是待查文档

这一整轮 3D 效果踩的坑，可以归成一类，值得当成方法论写下来：

**参数被接受 ≠ 参数有效 ≠ 结果如你所想。**

实测到的四种脱节，每一种都让"读文档 → 写参数"的做法失效：

| 类型 | 实例 |
| --- | --- |
| **参数变了，结果没变** | `PresetThreeDFormat` 接受值，但写出的投影不变；五个透视预设渲染完全相同 |
| **参数名和语义相反** | `Perspective = 0` 与 `= 1` 都是"关"，`-1` 才是"开" |
| **两个参数系统轴不对应** | 窗格 `RotationX/Y` 与 OOXML `lat/lon` 不是同一组数（§23） |
| **值域不合法时不是忽略，是拒绝** | `lat="-1800000"` 让 PowerPoint 判整个文件损坏（§26） |

**所以顺序应该是：**

1. **先扫参数空间**，把每个值渲染出来
2. **量一个可测的特征**（不是"看着像"）
3. **建立"参数 → 实测特征"的表**，需要时再回填文档里的语义

**关键在于第二步要选可量化的特征。** 这一轮用过的：

| 特征 | 量什么 | 判什么 |
| --- | --- | --- |
| **收敛比** = 远边宽 / 近边宽 | 剪影上下沿宽度 | 是否透视（1.000 = 平行） |
| **压扁度** = 高 / 中宽 | 剪影包围盒 | 倾角大小 |
| **错切方向** | 左右竖边长度差 | 深度往哪边退 |

**反面教材是我自己**：我先用"像不像平行四边形"挑姿态，而平行投影的矩形**在任何角度
都像平行四边形**，所以这个判据零区分力，直接导致选中了一个根本没躺下的姿态。
**换成"量远边是不是更窄"之后，一次就选中了。**
## 33. 测量值必须和它的**自变量**一起记录 —— 否则会写出错误的"规律"

2026-09-24，复现 `template1` 封面时踩到。这不是 COM 的坑，是**方法论的坑**，
但代价最贵（写了一条错规律进文档，还被用户当成依据），所以记在这里。

### 发生了什么

我在更早一轮探测里量到：给图片加 `scene3d`、把 `lat` 从 `0` 调到 `17400000`，
COM 读回尺寸从 `534×400` 变成 **`612×140`**（"被压扁 65%"）。我把这条写进了
`morph-and-3d-recipes.md §2.3`，并且**拿它去解释** `template1` 封面"为什么不重影"。

后来用真实文件 `template1.pptx` 复核：

| | `图片 8` 的 `off` | `ext` | `lat` |
| --- | --- | --- | --- |
| 第 1 页 | (67.9, 46.3) | **800×450** | `0` |
| 第 2 页 | (92.1, 172.6) | **800×450** | `17400000` |

**宽高恒为 800×450pt，位移 `dx=+24.1 / dy=+126.3`（⚠️ y 轴向下，`+`=下移）。**
根本不"压扁" —— 占位盒尺寸两页一个像素都没变。

### 根因

那次探测的样例**并不只有 `lat` 不同** —— `lon/rev` 也不全为 0，形状还叠了旋转。
我把"某一组 `(lat, lon, rev)` 下的结果"当成了"`lat` 的函数"来陈述。

### 正确的理解

- `a:off` / `a:ext` 是**占位盒**，不是**投影包围盒**。
  `lon=0` 时 3D 旋转**不改变占位盒**，PowerPoint 只按透视把它"斜插"进画面
  （近大远小）；内容仍在，不会因此"读不出人形"。
- 用 COM 读 `Shape.Width` / `Shape.Height` 拿到的也是占位盒，**反映不出投影**。

### 规则

1. **任何测量值都要在它旁边写清"在什么条件下测的"** ——
   这里是 `(lat, lon, rev)` 三元组 + 形状初始旋转。没有条件的数字是**谣言**。
2. 要把某个参数写成"规律"，**只改那一个参数、其它全部固定**，重测一遍。
3. 用测量值**解释另一个系统**（这里是 `template1`）之前，
   先用那个系统的真实文件复核一次。
4. 判断"3D 旋转有没有生效"，用两个独立证据：
   - COM 读回 `ThreeD.PresetCamera` = `62`（`-2` = 被拒）；
   - 渲染出来**目检投影形状**变了。
   **不要**指望 `Width/Height` 读回能反映投影。

## 38. 页间差值**有方向**：y 轴向下，别把加减号写反

**症状**：两页的 morph 都加了、配对形状也没加多余效果、素材也换成真截图了，
但第 2 帧**位置完全不对** —— 元素跑到了画面的另一半，还堵住了文字。

**根因**：读出了"`a:off` 的 y 从 46.3 变成 172.6"，却在写代码时写成
`y = P1_Y - ratio * H`（**上移**）。实际是**下移**。

```text
pptx 的 y 轴**向下增长**：
  图片 8 第1页 y=46.3  →  第2页 y=172.6
  dy = 172.6 - 46.3 = +126.3   ← 正数 = 向下
  下沿 496.3 → 622.6，被推出画布（540）之外
```

❌ 写成 `P1_Y - 0.2807*P1_H = -93.5` → 界面被抬到中上部，堵住标题；
   而且旋转在可见区里变窄后，看起来像"原地被压扁"，跟模板完全不是一个观感。

**排查顺序**：

1. **把两个数换成同一单位（pt）写在同一行**，标出 `+`/`−`：
   `P1 (67.9, 46.3)` → `P2 (92.1, 172.6)` → `dx=+24.1, dy=+126.3`。
2. **确认坐标轴方向** —— `pptx`/`EMU` 的 y 向下。`dy>0` 就是下移。
3. **看一眼下沿落点**：`172.6 + 450 = 622.6 > 540`，说明元素**被推出画面**。
   如果算出来还在画面内，方向多半错了。

> **差值是"有方向的量"，不是"变/不变"的布尔值。**
> 只记"变了"，就会在写代码时随手选一个符号。

**同源的第二层错**：以为"翻过去"是靠**缩放**。
实测 `图片 8` 两页的 `a:ext` **完全相同**（`10160428 × 5715241` EMU = 800×450pt）——
**宽高一个像素都没变**。"翻过去" = "整体下移 + 290° 透视把可见部分压窄"，
**不含缩放**。判据：**逐形状对比 `a:ext`，不变就说明不缩放。**

## 35. 抠图**盖不住**照片里那个人时，让它"虚" —— 不要硬撑尺寸

### 症状

封面第 2 帧出现"两个人"：一个是放大的清晰抠图，一个是 LAYER 照片里的本人。

### 为什么会盖不住（先量，别猜）

LAYER **下移** 126~132pt 后，LAYER 里照片主体的**占位盒上沿已经在画布外**
（实测 `y = -16.3`）。任何尺寸的抠图都会露头 —— 想靠"把抠图放大到盖住"
是**无解**的，放得越大，头顶越先出画布。

### template1 怎么做的

**它也没盖住。** 把它的第 2 帧渲染出来放大看：露出来的那个人是**虚的**，
读起来是"身后的残影/影子"，不是第二个人。

两边"幽灵区"的拉普拉斯方差实测：

| | 拉普拉斯方差 | 观感 |
| --- | --- | --- |
| template1 第 2 帧 | **16.2** | 柔和残影 |
| 扁平插画素材 | **255.0** | 锐利 16 倍 → 读作"两个人" |

差异来源：template1 的素材是**景深照片**（人清晰、背景虚化），
经三维旋转压扁后**自然失焦**；扁平插画全图等清晰度，不会自己虚。

### 修法

在**素材侧**给"照片里那个人"预置模糊，然后两帧共用同一张 LAYER 图
（morph 要求同形同名，不能两页换图）：

```python
# 只模糊主体那一块，羽化接缝，避免硬边
photo_small = canvas.resize((fw, fh), Image.LANCZOS)
soft = photo_small.filter(ImageFilter.GaussianBlur(14))
m = Image.new("L", (fw, fh), 0)
ImageDraw.Draw(m).rectangle([sx0-16, sy0-16, sx1+16, sy1+16], fill=255)
m = m.filter(ImageFilter.GaussianBlur(16))         # 羽化
photo_small = Image.composite(soft, photo_small, m)
```

- 第 1 帧：抠图盖在上面 → 看到清晰的人（模糊被遮住）
- 第 2 帧：露出柔和残影 → 与 template1 同观感

### 配套的两条

1. **第 1 帧的抠图要 `>= 1.0x` 照片里那个人**，否则 LAYER 里烘焙的本人会
   从边缘探头，头顶出现一圈残影。实测本人在 y `116.2..327.8`，
   `1.06x` 的抠图为 y `109.9..334.1`，刚好盖住还留 ~6pt 余量。
2. **抠图不要跟着 LAYER 的位移走**，方向也别猜。试过让抠图同步位移 132.5pt
   （当时仍以为 LAYER 是上移，所以做的是**上移**），结果头顶跑到画布外
   （COM 读回 `y=-41`），显示成"无头人"。
   template1 的做法是**人只放大、底边基本不动**：
   下沿 `430.4 → 481.2`（仅 +50.8，而 LAYER **下移**了 126.3 —— 位移量级
   和方向都跟抠图不是一回事）。

### 当时的误解

第一反应是"**没对齐**，把抠图调大就能盖住" —— 这是一个纯粹的尺寸思路，
前提是"只要够大就能覆盖"。第一次把它从 `0.86x` 调到 `1.06x`，
第 1 帧的头顶残影确实消失了，于是我认为问题解决。

但**第 1 帧能盖住，不代表第 2 帧能盖住**：第 2 帧 LAYER 下移之后，
照片里那个人的占位盒上沿已经跑到画布外（`y=-16.3`）。
我仍然沿着"调尺寸"的思路去试，甚至试到让抠图跟着 LAYER 一起位移
（按当时以为的"上移 132.5pt"，结果头顶出画布，成了"无头人"，COM 读回 `y=-41`）。

真正推翻它的是**把 template1 的第 2 帧放大看**：
它露出来的那个人**也是虚的** —— 作者根本没有试图去盖，而是让残留**软下来**。
一旦接受"盖不住"这个前提，"在素材侧预置模糊"就是唯一的解。
**我把一个"素材质感"问题当成了"尺寸"问题，多花了一整轮。**

## 36. 素材是"截图"还是"照片"，会改变整个观感 —— 先导出 `ppt/media/` 看一眼

### 症状

同一步"翻页"，template1 翻出来是**一片白**，我翻出来是**一道照片纹理**。

### 真身（导出 `ppt/media/` 实测，不是猜的）

| 文件 | 尺寸 | 真身 | 近白占比 |
| --- | --- | --- | --- |
| `image1.png` | 726×406 | 模糊压暗的照片（BG） | 0% |
| `image2.PNG` | 2560×1440 | **含 PowerPoint 界面的全屏截图**（LAYER） | **33.9%** |
| `image3.png` | 320×370 | 从截图里抠出的人（PERSON） | 4.8% |

LAYER 里**照片只占中央 `x 24.3%..78.6%`、`y 25.0%..81.4%`**，
其余全是界面白/灰。

### 教训

教程步骤 4 写的是「**全屏截图**，……大小调整到刚好覆盖第三步的图片，
删除第三步的图片，抠出图片中的人物」。我把它读成"截图只是抠图的中间产物"，
于是跳过了 —— 但**它就是 LAYER 素材本身**。

用干净照片当 LAYER，压扁后露出的是**照片纹理**；用界面截图，露出的是**白**。
这是"翻过去"能不能读出"白背面"的决定因素。

### 规则

复现别人的模板时，**先把 `ppt/media/` 全部导出、逐个看图**，
再决定每个 `rId` 到底喂什么。不要从形状名或尺寸去推断素材内容。

### 当时的误解

我记得自己**读到过**步骤 4 的"全屏截图"，但当时的判断是：
"截图只是为了从里面抠人 —— 抠完人，截图的使命就结束了"。
于是把 LAYER 直接喂了那张干净的原始照片，理由是"照片质量更好"。

支撑这个错误判断的是**一个从没验证过的假设**：我以为 LAYER 只是背景，
压扁之后"反正也看不清楚"。直到第 2 帧渲染出来，
露出的是**照片的纹理**而不是**白**，才发现 LAYER 在"翻过去"之后
**是被看清的**，它承载的不是背景，而是"被翻起来的那一页的正面观感"。

推翻它花的时间最短 —— **解包、导出 `ppt/media/`、看一眼 `image2.PNG`**，
看到那张近白占 33.9% 的界面截图，"必须复现"就成立了。
这也是四次教训里唯一一次"证据就在手边、只需要打开看"的错误。

## 37. "色块"替代不了"细节" —— 要复现一张截图，就去拿**真的**截图

### 症状

要复现 template1 的"翻页"封面，第 2 帧翻起来是**一块硬边灰板**横在画面中间，
像"渲染坏了一半"。用户原话：**"真的非常，诡异"**。

### 当时我是怎么做的（错在哪）

教程步骤 4 写着"全屏截图"。我认定"必须复现"这一步 —— 然后**自己画了一张**：

```python
ui = Image.new("RGB", (1920, 1080), (240, 240, 240))     # 灰壳
dr.rectangle(...fill=(255,255,255))                       # 几条白面板
dr.rectangle(...fill=(252,252,252))                       # 一个白方块当画布
```

色号抄得很像（灰壳 + 白栏 + 白画布），**但它是"色块"，不是"截图"**。
压扁之后：色块 → 一块灰板；截图 → 纸背。

### 为什么"像"不等于"是"

真实截图的**近白占比**和假 UI 差不多（template1 实测 31.7%）——
**统计量对得上，观感完全不对**。差别在**细节密度**：工具栏图标、缩略图、
面板控件、参考线、选中控制点……这些高频纹理在三维旋转压扁后**仍在**，
它们承担了"这是一张纸"的全部信号。

**用色号复现一张截图，是把信息量从"几万条边缘"降到"四个矩形"。**
无论色号多准，都不可能像。

### 规则

1. **要复现"某张图"，就去拿那张图**（解包 `ppt/media/`），
   不要把它的"配色"抄下来重画。重画只能复现配色，不能复现质感。
2. **不要把统计量当"看过了"** —— "近白 33.9%" 这个数字我上一轮就拿到了，
   却仍然把它读成"干净的空白界面"。**数字要配合"真的打开看一眼"。**
3. 判据：**如果你能用五个 `draw.rectangle` 复现它，那它多半不是截图。**

### 当时的误解

我把"复现"理解成"复现它的**属性**"（是白的、占满屏、有边框），
而不是"复现这个**物体**"。支撑这个错判的是一个偷懒的推理：
"反正三维旋转后都被压扁了，细节看不清，色块够用。"

推翻它的方式极简单，也正是这一轮最大的教训：
**把 template1 的第 1/2 帧渲染出来，放大看。** 一看就明白
——真实截图里那些被压扁的图标、缩略图边框、控制点，一个都没消失，
它们就是"纸背"的全部来源。

## 39. 露出的底（BG）**必须有可辨认的内容**，否则就是一块空白板

**症状**：第 2 帧上方露出的背景是**一片近白**，像一块空的白色板子，
让整个画面显得没做完。

**根因**：为了让冷白的插画底"变暖"，叠了一串后期：

```text
放大 1.35 → 模糊 48 → 饱和 1.85 → blend(暖米 0.55) → 亮 1.06
```

每一环都在**抹掉内容**、往纯色推。实测 RGB 均值 **239/252/254** —— 基本是白。

而 template1 第 2 帧露出的底（`图片 4`）**仍然是同一张照片放大+模糊**，
**看得清天空、山丘、云**。它有可辨认的内容，所以读作"翻过去后露出的那张画"。

**判据（和 §37 同源）**：
**如果你能用五个 `draw.rectangle` 复现它，那它多半不是背景，是一块色块。**

**修法：每一环都往"保留内容"的方向调。**

| 参数 | 错的值 | 对的值 | 理由 |
| --- | --- | --- | --- |
| 放大 | 1.35 | **1.55** | 太小则底图人物和清晰人物**叠成一个黑团**；放大到头部出画，只剩身体色块 |
| 模糊 | 48 | **28** | 48 抹掉一切；28 保留"这里有一幅画"的轮廓 |
| 饱和 | 1.85 | **1.15** | 1.85 冲成一片；1.15 只轻提暖色 |
| 暖调 blend | 0.55 | **0.18** | 0.55 直接洗白 |

**附带一条**：底图里的人物如果和上层清晰人物**对齐**，两个头会叠在一起
（深色发髻尤其明显），看起来像渲染错误。**放大到把底图人物的头推出画面上沿**，
只留身体/衣物的色块 —— 既保留内容感，又不打架。

### 当时的误解

我把"把它拉暖"理解成"往上叠暖色"，于是叠加层数越多越好、
不透明度越高越好。**但暖色叠加是"减法"——它在减去原图的信息。**
正确做法是**提高源素材里暖色面积占比**（放大取局部），而不是盖一层暖色。

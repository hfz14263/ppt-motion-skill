### §33 测量值必须和它的**自变量**一起记录 —— 否则会写出错误的"规律"

<a id="s10"></a>

**现象**：记录了一批测量值，拟出一条「规律」，换个样本就完全不成立

不是 COM 的坑，是**方法论的坑**，但代价最贵：一条错规律写进文档后，
还被当成依据去解释别的系统。

我量到"图片加 `scene3d`、`lat` 从 `0` 调到 `17400000`，COM 读回 `534×400 → 612×140`
（压扁 65%）"，写进文档后**拿它去解释** template1 封面。真实文件复核：

| | `图片 8` 的 `off` | `ext` | `lat` |
| --- | --- | --- | --- |
| 第 1 页 | (67.9, 46.3) | **800×450** | `0` |
| 第 2 页 | (92.1, 172.6) | **800×450** | `17400000` |

**根本不"压扁"** —— 占位盒两页一个像素都没变。那次探测的样例 `lon/rev` 也不全为 0、
形状还叠了旋转，我把"某一组 `(lat,lon,rev)` 下的结果"当成了"`lat` 的函数"。

1. `a:off`/`a:ext` 是**占位盒**，不是投影包围盒；COM 读 `Width/Height` 也是占位盒。
2. 要写"规律"，**只改那一个参数、其它全部固定**重测。
3. 用测量值**解释另一个系统**前，先用那个系统的真实文件复核。

4. 判断"3D 旋转生效没"：`ThreeD.PresetCamera` = `62`（`-2` = 被拒）+ **渲染目检**。

### §34 「翻过去」是**下沉 + 三维旋转**两件事 —— 只做旋转得到"被压扁的一页"

<a id="s11"></a>

**现象**：翻页时第1 帧正常、第 2 帧像「照片被压扁了一下」

第 1 帧正常，第 2 帧只像"照片被压扁了一下"（用户原话："真的非常，诡异"）。
动画字段全读得回来、`verify_motion` 全绿 —— **纯几何问题，校验器抓不到**。

实测（template1，画布 960×540）：`图片 8` 的 `off` `(67.9,46.3) → (92.1,172.6)`，
`ext` **两页都是 800×450**，`lat` `0 → 17400000`。**`dx=+24.1`、`dy=+126.3`，宽高严格不变。**

- LAYER 下沿 `496.3 → 622.6`，**被推出画布外**（画布高 540）；
- 留在画面里的只剩它经 290° 旋转压扁后的上半部分；
- 于是露出底下的模糊底 —— **这才是"翻过去的那一页背面"**。

⚠️ **y 轴向下增长，`dy=+126.3` 是下移。** 我第三遍仍做成上移，界面被抬到中上部堵住标题。见 §38。

1. 教程里出现**「移动/移动到」**，当成**独立的几何变换**去找数值，别默认旋转会顺带位移。
2. 复现"翻页/揭开"类 morph，**同时检查两件事**：`a:off` 变没变 + `a:scene3d/a:rot` 变没变。

3. 抄相对量用**比例**（`dx/宽`、`dy/高`）：template1 是 `24.1/800=0.0302`、`126.3/450=0.2807`。


推翻误判只需要**下沿的算术**：`172.6+450=622.6 > 540`。
**不需要渲染、不需要 COM，只要把两页的 `a:off` 各读一遍。**

**根因与修法**：见 [`pitfall-morph-3d.md`](pitfall-morph-3d.md) §34。

### §35 抠图**盖不住**照片里那个人时，让它"虚" —— 不要硬撑尺寸

<a id="s12"></a>

**现象**：抠图盖不住照片里那个人，封面出现「两个人」

封面第 2 帧出现"两个人"：一个是放大的清晰抠图，一个是 LAYER 照片里的本人。

LAYER **下移** 126~132pt 后，LAYER 里照片主体的**占位盒上沿已在画布外**（实测 `y=-16.3`）。
任何尺寸的抠图都会露头 —— **无解**，放得越大，头顶越先出画布。

**template1 也没盖住**：它第 2 帧露出来的人是**虚的**，读作"身后的残影"。
两边"幽灵区"拉普拉斯方差实测：

| | 拉普拉斯方差 | 观感 |
| --- | --- | --- |
| template1 第 2 帧 | **16.2** | 柔和残影 |
| 扁平插画素材 | **255.0** | 锐利 16 倍 → 读作"两个人" |

差异来源：template1 的素材是**景深照片**，压扁后**自然失焦**；扁平插画全图等清晰度，不会自己虚。

**修法（在素材侧预置模糊，两帧共用同一张 LAYER 图）**：

```python
soft = photo_small.filter(ImageFilter.GaussianBlur(14))
m = Image.new("L", (fw, fh), 0)
ImageDraw.Draw(m).rectangle([sx0-16, sy0-16, sx1+16, sy1+16], fill=255)
m = m.filter(ImageFilter.GaussianBlur(16))          # 羽化接缝，避免硬边
photo_small = Image.composite(soft, photo_small, m)
```

- 第 1 帧：抠图盖在上面 → 清晰的人（模糊被遮住）

- 第 2 帧：露出柔和残影 → 与 template1 同观感


配套两条：第 1 帧抠图须 `>= 1.0x` 照片里那个人（实测本人 y `116.2..327.8`，
`1.06x` 抠图 y `109.9..334.1`，余量 ~6pt）；**抠图不要跟着 LAYER 的位移走**
（试过同步位移 132.5pt → COM 读回 `y=-41`，"无头人"）。

**根因与修法**：见 [`pitfall-media.md`](pitfall-media.md) §35。

### §36 素材是"截图"还是"照片"，会改变整个观感 —— 先导出 `ppt/media/` 看一眼

<a id="s13"></a>

**现象**：同一套翻页，template1 翻出来是一片白，我翻出来是一道照片纹理

同一步"翻页"，template1 翻出来是**一片白**，我翻出来是**一道照片纹理**。

真身（导出 `ppt/media/` 实测）：

| 文件 | 尺寸 | 真身 | 近白占比 |
| --- | --- | --- | --- |
| `image1.png` | 726×406 | 模糊压暗的照片（BG） | 0% |
| `image2.PNG` | 2560×1440 | **含 PowerPoint 界面的全屏截图**（LAYER） | **33.9%** |
| `image3.png` | 320×370 | 从截图里抠出的人（PERSON） | 4.8% |


LAYER 里**照片只占中央 `x 24.3%..78.6%`、`y 25.0%..81.4%`**，其余全是界面白/灰。

用干净照片当 LAYER，压扁后露出**照片纹理**；用界面截图，露出**白** ——
这是"翻过去"能不能读出"白背面"的**决定因素**。

**规则**：复现别人的模板，**先把 `ppt/media/` 全部导出、逐个看图**，
再决定每个 `rId` 喂什么。**不要从形状名或尺寸推断素材内容。**

**根因与修法**：见 [`pitfall-media.md`](pitfall-media.md) §36。

### §37 "色块"替代不了"细节" —— 要复现一张截图，就去拿**真的**截图

<a id="s14"></a>

**现象**：想复现模板里的翻页，渲染出来是一块硬边灰板横在画面中间

第 2 帧翻起来是**一块硬边灰板**横在画面中间，像"渲染坏了一半"。

我按教程"全屏截图"自己**画了一张**（灰壳 + 几条白面板 + 一个白方块当画布）。
色号抄得很像，**但它是"色块"，不是"截图"**。

真实截图的**近白占比**和假 UI 差不多（template1 实测 31.7%）——

**统计量对得上，观感完全不对**。差别在**细节密度**：工具栏图标、缩略图、

面板控件、参考线、选中控制点……这些高频纹理压扁后**仍在**，
它们承担了"这是一张纸"的**全部**信号。

1. **要复现"某张图"，就去拿那张图**（解包 `ppt/media/`），别把配色抄下来重画。
2. **不要把统计量当"看过了"** —— 数字要配合"真的打开看一眼"。
3. 判据：**如果你能用五个 `draw.rectangle` 复现它，那它多半不是截图。**

**根因与修法**：见 [`pitfall-media.md`](pitfall-media.md) §37。

### §39 露出的底（BG）**必须有可辨认的内容**，否则就是一块空白板

<a id="s16"></a>

**现象**：需要露出的底，渲染出来是一块空白板

第 2 帧上方露出的背景是**一片近白**，像一块空的白色板子，整个画面显得没做完。

根因：为了让冷白的插画底"变暖"，叠了一串后期
`放大1.35 → 模糊48 → 饱和1.85 → blend(暖米0.55) → 亮1.06` ——
**每一环都在抹掉内容**。实测 RGB 均值 **239/252/254**，基本是白。

而 template1 露出的底**仍是同一张照片放大+模糊**，**看得清天空、山丘、云**。

| 参数 | 错的值 | 对的值 | 理由 |
| --- | --- | --- | --- |
| 放大 | 1.35 | **1.55** | 太小则底图人物与清晰人物**叠成一个黑团**；放大到头部出画，只剩身体色块 |
| 模糊 | 48 | **28** | 48 抹掉一切；28 保留"这里有一幅画"的轮廓 |
| 饱和 | 1.85 | **1.15** | 1.85 冲成一片；1.15 只轻提暖色 |
| 暖调 blend | 0.55 | **0.18** | 0.55 直接洗白 |

> **暖色叠加是"减法"——它在减去原图的信息。**
> 正确做法是**提高源素材里暖色面积占比**（放大取局部），不是盖一层暖色。

**附带一条**：底图人物若与上层清晰人物**对齐**，两个头会叠在一起（深色发髻尤其明显），
看起来像渲染错误。**放大到把底图人物的头推出画面上沿**，只留身体/衣物色块。

**根因与修法**：见 [`pitfall-media.md`](pitfall-media.md) §39。

## 0. 先做这一步（别跳）

<!-- gen:preflight:start -->
**0. 先扫一遍 shape，拿到真实 id —— 不要手写。**

```bash
python scripts/motion.py inspect --pptx deck.pptx
```

**为什么放在最前面**：手写形状 id 列表是本项目最贵的错误来源。
deck 改一次版式，id 就全体重排，spec 于是指向了**别的形状** ——
不是报错，是**静默错位**（曾经整张卡没动画，而且正好差一位）。

**1. 判断素材形态**（打开 deck 一眼能看出的东西，这是唯一已知量）

| 看到什么 | 往哪走 |
| --- | --- |
| 一张照片 / 一个居中物体 | 「主体是张图」那一支 |
| 一张图想分块控制 | 「切成几块」那一支 |
| 一个平面对象（照片、卡片、图表） | 「立体感」那一支 |
| 多页连续内容 | 「多页连贯叙事」那一支 |

**2. 只动一个变量**

这是最容易违反的一条：`motion-lives-between-pages` 要求两页形状
name/id 完全一致，**只改要动的那几个数值**。多改一个，两个页就配不上对，
Morph 退化成淡入 —— 而你看到的是"效果没生效"，不是"配对失败"。

**3. 拿 §3 的失败信号验收，不要自我感觉**

做完对着 §3 逐条看。长成那样就是错了。

## 2. 配方速查：什么时候用哪条

<!-- gen:table:start -->
| # | 原理 | 什么时候用 | 一句话 |
| --- | --- | --- | --- |
| 1 | **动效来自页与页的差异，不是页内动画** | 素材是现成 pptx，且愿意为动效多排几页<br>想让观众注意**两页之间的变化**，而不是某页内部的表演<br>需要页面级连贯感（同一组图逐页展开） | 多页 + 切换 = 动效。页内 <p:timing> 是另一回事：跨页延续的形状**不能**带页内 entrance（会退出补间），过渡整体交给页面切换。 |
| 2 | **动遮罩，不动图** | 主体是**一张图**或**一个居中的物体**（花、logo、产品、建筑）<br>想让这张图**被展开**而不是**被移动**<br>已经确认照片里没有可分离的多个对象 | 图固定（常在页面背景），形状是窗口，绕主体上的轴心旋转。补间的是窗口的角度，不是图的位置。 |
| 3 | **形状可以拼回整图，也可以切开整图** | 想把一张整图**切成几块**分别控制，或反过来**拼回整图**<br>需要每块单独动，但内容必须严丝合缝对得上原图 | 给每个形状一个窗口内缩，N 个形状就能无缝拼回原图；改内缩就是【切】，不改就是【拼】。 |
| 4 | **「平面→立体」是两页之间的差异，不是页内把图拧一下** | 画面里是**一个平面对象**（照片、卡片、图表），需要看起来有厚度/倾斜<br>想要立体感但不愿意建模 | 在单页里扭一个平面，得到的是【一张歪掉的图】；平面一页 + 立体一页 + Morph，得到的才是【变成了另一个东西】。 |
| 5 | **没有 Morph 时，可以手写中间帧** | 目标 PowerPoint 版本**不支持 Morph**，或本机没有 Morph 可用<br>中间姿态需要人工控制（不想让 PowerPoint 自动插值） | 把中间姿态逐页写出来，用页面推进当补间。代价是页数，收益是不依赖版本。 |
| 6 | **图片 × 形状的联动，才是设计感所在** | 拿不准该动图还是该动形状（这是元配方，其余五条的具体化）<br>做完一版但读起来像**整体移动**而不是**揭示** | 形状决定【露出哪一块】，图片决定【露出什么】。两者分离，才既有结构又有内容。 |

## 4. 这棵树为什么长这样

**树按「素材形态」分叉，不按「想做什么效果」分叉。**

按效果分叉会退化成效果清单 —— 效果是无穷的，遇到没见过的就卡住。
按素材形态分叉只有四个问题，而**素材是接手时唯一确定已知的东西**
（打开 deck 一眼就能看出来），效果是猜的。

**"失败信号"比"适用条件"更重要。** 绝大多数坑不是"不知道怎么做"，
而是"做出来了但读法不对"。所以每条配方都先记坏掉时的症状，
拿它当**验收标准** —— 长成那样就是错了，不用等别人告诉你。

## 5. 这棵树会腐烂

**生成器只覆盖表格与树，判据在脚本里。** 手改生成结果会在下次重跑时被覆盖，
而 `--check` 会当场发现不一致（CI / 提交前跑）。

所以**要改内容就改 `recipes.json`**，那是唯一真相源。
加配方请照 [`recipe-library.md`](recipe-library.md) §4 的字段要求补全，
少补 `applicable_when` 或 `breaks_how` 的话生成器会报错——这是刻意的：
**没有失败信号的配方不能进树**，因为它无法被验收。
